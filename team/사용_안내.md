# B200 서버 사용 안내

이 문서를 따라 하면 내 PC에서 짠 코드와 도커 이미지를 서버에 올려, 내가 고른 GPU에서 학습을 돌리고 결과를 내려받을 수 있어요.
규칙은 `서버_사용_규칙.md`에 있어요.
**새로 외울 명령은 없어요.** 평소 쓰던 `docker`, `nvidia-smi`, FileZilla를 그대로 써요.

## 한눈에 보는 흐름

| 순서 | 어디서 | 할 일 | 명령 |
|---|---|---|---|
| 1 | 내 PC | 코드를 짜고 도커 이미지를 만들어 파일로 저장 | `docker build`, `docker save` |
| 2 | FileZilla | 코드와 이미지 파일을 내 작업 폴더에 올리기 | 끌어다 놓기 |
| 3 | 서버 | 이미지 들여오기 | `docker load` |
| 4 | 서버 | 빈 GPU를 보고 컨테이너 만들기(한 번) | `nvidia-smi`, `docker run` |
| 5 | 서버 | 컨테이너에 들어가 실행하고, 간단한 수정도 그 안에서 | `docker exec` |
| 6 | FileZilla | 결과 내려받기 | 끌어다 놓기 |
| 7 | 서버 | 다 쓰면 GPU 놓기 | `docker stop` |

## 1. 내 PC에서 준비

서버에는 인터넷이 없어요. **필요한 패키지는 모두 이미지에 넣어서** 가져와요.

```bash
# [내 PC] 도커가 있는 PC나 워크스테이션
docker build --platform linux/amd64 -t myseg:v1 .
docker save -o myseg_v1.tar myseg:v1
```

- **`--platform linux/amd64`로 빌드해요.** Mac(Apple Silicon)은 기본이 arm64라서 서버에서 실행되지 않아요.
- **B200을 지원하는 PyTorch를 써요.** CUDA 12.8 이상으로 빌드한 PyTorch 2.7 이상이어야 해요. 그보다 오래된 이미지는 `no kernel image is available` 오류가 나요. NVIDIA 공식 이미지(`nvcr.io/nvidia/pytorch`)의 최근 태그를 바탕으로 쓰면 안전해요.
- 코드는 이미지에 넣지 않아도 돼요. 코드는 작업 폴더에 따로 올리면 고치기가 쉬워요(5단계).

## 2. 올리기 (FileZilla)

| 무엇 | 서버의 어디로 |
|---|---|
| 코드 | `/app/workspace/<내 이름>/<프로젝트>` |
| 이미지 파일(`.tar`) | `/app/workspace/<내 이름>/images` |

- 큰 파일 전송이 끊기면 다시 올릴 때 **이어받기**를 고르세요.
- 홈 폴더(`~`)는 모두가 같이 쓰는 10 GB라 파일을 두지 않아요.

## 3. 접속하고 이미지 들여오기

HIWARE로 접속하면 GPU 현황과 이름 목록이 나와요. 내 번호를 입력하세요.

```text
B200 서버 (server1)  팀원 모두가 공용 계정으로 써요. 이름을 고르면 GPU·컨테이너 옆에 이름이 보여요.
누가 쓰나  (공용 계정이라 접속할 때 고른 이름으로 보여요)
GPU 배분           쓰는 사람       사용률 메모리 GB 컨테이너
0   자율주행매니저 -               0%     0/179     -
1   인지           김철수          97%    71/179    kcs-train
...
  이름을 고르세요(번호나 이름):
   1 홍길동   2 김철수   3 이영희
  > 1
[홍길동] shareduser@b200:/app/workspace/홍길동$
```

- 이름을 고르면 내 작업 폴더로 이동하고, 내 컨테이너와 GPU 옆에 이름이 붙어요.
- 명단에 이름이 없으면 관리자에게 등록을 요청하세요.
- 서버 2는 다른 팀과 같이 써요. 0~3번은 배분 칸에 "다른 팀" 으로 보이니 쓰지 말고, 4~7번만 써요.

```bash
docker load -i images/myseg_v1.tar    # 이미지 들여오기
docker images                         # 확인
rm images/myseg_v1.tar                # 들여왔으면 파일은 지워서 공간을 비워요
```

`docker images` 목록에 `myseg` `v1` 이 보이면 돼요.

## 4. 빈 GPU를 보고 컨테이너 만들기

`nvidia-smi` 아래에 **누가 쓰나** 표가 붙어 나와요. 내 그룹이나 공용에서 빈 GPU를 고르세요.

```bash
docker run -dit --name hong-seg \
  --gpus '"device=5"' --shm-size 32g \
  -v /app/workspace/홍길동:/workspace -v /app/shared:/app/shared:ro \
  -w /workspace myseg:v1 bash
```

| 옵션 | 뜻 |
|---|---|
| `-dit` | 컨테이너를 뒤에서 켜 둬요. 접속이 끊겨도 계속 켜져 있어요 |
| `--name hong-seg` | 컨테이너 이름. **영어·숫자·`-`만** 돼요. 내 이름표는 자동으로 붙어요 |
| `--gpus '"device=5"'` | 쓸 GPU 번호. 2장이면 `'"device=5,6"'` |
| `--shm-size 32g` | 데이터 로더(`num_workers`)가 멈추지 않게 공유 메모리를 넉넉히 줘요 |
| `-v /app/workspace/홍길동:/workspace` | 내 작업 폴더를 컨테이너 안 `/workspace`로 연결해요. 안에서 고친 파일이 그대로 남아요 |
| `-v /app/shared:/app/shared:ro` | 공용 데이터셋·모델(읽기만) |

`docker ps` 의 USER 칸에 내 이름, GPUS 칸에 고른 번호가 보이면 돼요.

남이 쓰는 GPU를 고르면 실행 전에 이렇게 경고하고 한 번 물어봐요.

```text
  [경고] GPU 1번은 지금 김철수 님이 쓰고 있어요. 같이 쓰면 메모리가 모자라 둘 다 멈출 수 있어요.
  내 그룹·공용의 빈 GPU: 5 6 7   (현황: nvidia-smi)
  그래도 실행할까요? [y/N]
```

- `--gpus all`이나 `--gpus 2`(장 수만)는 쓰지 마세요. 0번부터 잡아서 다른 사람과 겹쳐요.
- 컨테이너의 GPU는 만든 뒤에 바꿀 수 없어요. 바꾸려면 컨테이너를 새로 만들어요(안에서 설치한 것이 있으면 먼저 `docker commit`).

## 5. 컨테이너에서 실행하고 고치기

```bash
docker exec -it hong-seg bash        # 들어가기. 창을 여러 개 열어도 돼요
python train.py --epochs 1           # 확인 삼아 실행
exit                                 # 나와도 컨테이너는 계속 켜져 있어요
```

**접속이 끊겨도 계속 돌아야 하는 학습**은 `-d`로 뒤에서 실행하고, 기록은 파일로 봐요.

```bash
docker exec -d hong-seg bash -c 'python train.py > train.log 2>&1'
tail -f train.log                    # 서버에서 바로 볼 수 있어요(Ctrl+C로 나와도 학습은 계속)
```

화면을 붙였다 뗐다 하고 싶으면 `tmux`를 써도 돼요(`tmux` → `docker exec -it hong-seg python train.py` → `Ctrl+b` 누른 뒤 `d`, 다시 볼 때는 `tmux attach`). 사람마다 tmux가 따로라 남의 창과 섞이지 않아요.

**간단한 수정**은 세 가지 방법 중 편한 것으로 해요. 모두 같은 파일을 고치는 거예요.

| 방법 | 어떻게 |
|---|---|
| 컨테이너 안에서 | `vim train.py` (이미지에 편집기가 있을 때) |
| 서버에서 | 컨테이너 밖 `/app/workspace/<내 이름>`에서 `micro train.py`(Ctrl+S 저장, Ctrl+Q 나가기) 또는 `vim` |
| 내 PC에서 | FileZilla에서 파일을 오른쪽 클릭 → **보기/편집**. 저장하면 서버로 다시 올릴지 물어봐요. 편집기는 FileZilla 설정에서 VS Code 등으로 바꿀 수 있어요 |

**패키지를 더 설치할 때**는 서버에 인터넷이 없으니 내 PC에서 받아 와요. 계속 쓸 패키지면 Dockerfile에 넣어 이미지를 다시 만드는 게 가장 깔끔해요.
급할 때는 내 PC에서 **같은 이미지로** 받아 올리면 Python 판과 플랫폼이 저절로 맞아요.

```bash
# [내 PC] 같은 이미지 안의 pip 으로 받아 wheels 폴더에 모아요
docker run --rm --platform linux/amd64 -v "$PWD/wheels:/w" myseg:v1 pip download timm einops -d /w
```

`wheels` 폴더를 FileZilla로 `/app/workspace/<내 이름>/wheels` 에 올린 뒤 컨테이너 안에서 설치해요.

```bash
pip install --no-index --find-links /workspace/wheels timm einops   # 컨테이너 안에서
```

- 컨테이너 안에서 설치한 것은 `docker stop`·`start`를 해도 남지만, `docker rm`하면 사라져요. 계속 쓰려면 `docker commit hong-seg myseg:v2`로 이미지에 저장하세요.
- 컨테이너 안에서 만든 파일도 FileZilla로 바로 내려받고 지울 수 있어요. 단, `docker run --user`는 쓰지 마세요. 파일 주인이 달라져 FileZilla로 지울 수 없게 돼요.

## 6. 결과 내려받기

FileZilla로 `/app/workspace/<내 이름>`에서 내려받아요.

## 7. 다 쓰면

```bash
docker stop hong-seg      # GPU 놓기. 다시 쓸 때: docker start hong-seg
docker rm hong-seg        # 컨테이너 지우기
docker rmi myseg:v1       # 이미지도 필요 없으면
```

GPU를 잡은 채로 12시간 동안 사용률이 0%면 알림이 와요. 끝난 컨테이너는 `docker stop`으로 놓아 주세요.

## 현황 보기

| 보고 싶은 것 | 명령 |
|---|---|
| GPU별 쓰는 사람, 사용률, 컨테이너 | `nvidia-smi` (아래 **누가 쓰나** 표) |
| 컨테이너와 주인(USER), GPU | `docker ps` |
| 내 폴더 크기 | `du -sh /app/workspace/<내 이름>` |

## 알림

서버가 10분마다 GPU와 디스크를 보고, 필요할 때만 알려 줘요. 멈추거나 지우지는 않아요.

| 알림 | 언제 | 얼마나 자주 |
|---|---|---|
| GPU 겹침 | 한 GPU를 두 사람 이상이 쓸 때 | 하루 한 번 |
| 놀고 있는 GPU | GPU를 잡고 12시간 내내 사용률 0% | 하루 한 번 |
| 디스크 | `/app`이 85%를 넘으면 많이 쓰는 3명에게 | 주 한 번 |
| 오래된 이미지 | 들여온 이미지를 30일 동안 안 쓰면 | 주 한 번 |

알림은 열어 둔 창에 한 줄로 뜨고, 다음에 접속할 때도 보여 줘요.

## 서버 화면에서 쓰는 명령

서버에는 공용 Python 환경이 없어요. 학습은 도커 컨테이너에서 해요.
컨테이너 밖 서버 화면에서는 기초 프로그램을 바로 쓸 수 있어요: `tmux`, `nvtop`, `htop`, `ncdu`(폴더 크기), `rsync`, `vim`, `git`, `unzip` 등.

## 데이터셋과 모델 불러오기

서버에는 인터넷이 없어서, Hugging Face에 접속하지 않도록 설정이 미리 돼 있어요. 컨테이너 안에서는 `-e HF_HUB_OFFLINE=1`을 붙이거나 코드에서 경로로 불러와요. 컨테이너 안에서도 경로는 서버와 같은 `/app/shared/...`예요.

```python
from pathlib import Path
M = Path("/app/shared/models")

# transformers
from transformers import AutoModel
model = AutoModel.from_pretrained(M / "facebook/dinov3-vitl16-pretrain-lvd1689m")
model = AutoModel.from_pretrained(M / "nvidia/C-RADIOv4-H", trust_remote_code=True)   # 코드 파일도 같이 들어 있어요

# timm: 가중치 파일을 직접 지정해요
import timm
model = timm.create_model(
    "vit_large_patch16_dinov3.lvd1689m", pretrained=True,
    pretrained_cfg_overlay={"file": str(M / "timm/vit_large_patch16_dinov3.lvd1689m/model.safetensors")},
)

# 깊이: Depth Anything V2
from transformers import pipeline
depth = pipeline("depth-estimation", model=str(M / "depth-anything/Depth-Anything-V2-Metric-Outdoor-Large-hf"), device=0)
```

**GOOSE-M2F**(GOOSE로 학습한 Mask2Former)는 모델 구조가 함께 받은 코드에 있어요.

```python
import sys, torch
G = M / "XYZ9843/GOOSE-M2F"
sys.path.insert(0, str(G / "code"))
from src.model import GOOSEMask2Former   # 사용법: G / "code/instructions/instructions.md"
ckpt = torch.load(G / "best_model.pth", map_location="cpu", weights_only=False)
```

- 코드 안에서 `facebook/mask2former-swin-large-cityscapes-semantic`을 이름으로 부르는 곳은 `str(M / "facebook/mask2former-swin-large-cityscapes-semantic")` 경로로 바꾸세요.
- Depth Anything 3(`DA3METRIC-LARGE`, `DA3MONO-LARGE`)는 `depth_anything_3` 코드가 필요해요. 이미지에 넣어 오세요.

| 데이터셋 | 라벨 위치 (`/app/shared/datasets/` 아래) |
|---|---|
| GOOSE | `goose/goose_2d_*/labels/**/*_labelids.png` |
| GOOSE-Ex | `gooseEx/gooseEx_2d_*/labels/**/*_labelids.png` |
| RUGD | `RUGD/RUGD_annotations/*/*.png` |

있는 모델과 데이터셋은 엑셀 '모델 목록', '데이터셋 목록' 시트에서 볼 수 있어요.

## Jupyter·TensorBoard·VS Code

지금 HIWARE에서는 PuTTY와 FileZilla만 돼요. 내 PC 브라우저로 Jupyter·TensorBoard를 보려면 **포트 연결(SSH 터널)** 이, VS Code로 서버에 붙으려면(Remote-SSH) 내 PC에서 서버로 **SSH 직접 접속** 이 허용돼야 해요. 둘 다 보안 담당의 허락이 필요해서, 그 전까지는 이렇게 해요.

| 하고 싶은 것 | 지금 할 수 있는 방법 |
|---|---|
| TensorBoard | 로그 폴더(`runs`)를 FileZilla로 내려받아 내 PC에서 `tensorboard --logdir runs` |
| Jupyter | 노트북을 컨테이너 안에서 통째로 실행하고(이미지에 jupyter가 있어야 해요), 결과가 담긴 노트북을 내려받아요: `jupyter nbconvert --to notebook --execute --inplace 실험.ipynb` |
| VS Code | FileZilla **보기/편집**의 편집기를 VS Code로 정하면, 저장할 때 서버로 올라가요(5단계). 편집만 되고 터미널·디버깅은 안 돼요 |

## 자주 묻는 질문

| 상황 | 할 일 |
|---|---|
| 컨테이너 안에서 `torch.cuda.is_available()`가 False예요 | `docker run`에 `--gpus '"device=번호"'`를 빼먹었어요(만들 때 `--gpus 옵션이 없어서 GPU 없이 실행해요` 알림이 떠요). 컨테이너를 새로 만드세요 |
| `no kernel image is available` | B200을 지원하지 않는 PyTorch예요. 1단계의 PyTorch 조건을 보세요 |
| `exec format error` | arm64로 빌드한 이미지예요. `--platform linux/amd64`로 다시 빌드하세요 |
| 데이터 로더가 멈추거나 `bus error` | `--shm-size 32g`를 빼먹었어요 |
| `docker run`에서 `Conflict. The container name ... is already in use` | 같은 이름의 컨테이너가 있어요. `docker ps -a`로 보고 `docker start`하거나 이름을 바꾸세요 |
| `pip install`이 인터넷에 연결하려다 실패해요 | 서버에는 인터넷이 없어요. 5단계 "패키지를 더 설치할 때" 처럼 내 PC에서 받아 올려 `--no-index --find-links /workspace/wheels`로 설치하세요 |
| `/app/shared`에 파일을 못 써요 | 공용 폴더는 읽기만 돼요. 추가가 필요하면 관리자에게 요청하세요 |
| 내 컨테이너가 `docker ps`의 USER 칸에 안 보여요 | 이름을 고르지 않고 접속했어요(만들 때 `이름을 고르지 않아` 알림이 떠요). 다시 접속해 이름을 고른 뒤 컨테이너를 새로 만드세요 |
