# GPU 서버 사용 안내

이 문서를 따라 하면 내 PC에서 짠 코드와 도커 이미지를 서버에 올려, 내가 고른 GPU에서 학습을 돌리고 결과를 내려받을 수 있어요.
규칙은 `서버_사용_규칙.md`에 있어요.
**새로 외울 명령은 없어요.** 평소 쓰던 `docker`, `nvidia-smi`, FileZilla를 그대로 써요.

## 한눈에 보는 흐름

| 순서 | 어디서 | 할 일 | 명령 |
|---|---|---|---|
| 1 | 내 PC | 코드를 짜고 도커 이미지를 만들어 파일로 저장 | `docker build`, `docker save` |
| 2 | FileZilla | 코드와 이미지 파일을 내 작업 폴더에 올리기 | 끌어다 놓기 |
| 3 | 서버 | 이미지 들여오기 | `docker load` |
| 4 | 서버 | 빈 GPU를 보고 컨테이너 만들기(처음 한 번) | `nvidia-smi`, `docker run` |
| 5 | 서버 | 컨테이너에 들어가 실행하고, 간단한 수정도 그 안에서 | `docker exec` |
| 6 | FileZilla | 결과 내려받기 | 끌어다 놓기 |
| 7 | 서버 | 다 쓰면 GPU 놓기 | `docker stop` |

## 1. 내 PC에서 준비

서버에는 인터넷이 없어요. **필요한 패키지는 모두 이미지에 넣어서** 가져와요.

```bash
# [내 PC] 도커가 있는 PC나 워크스테이션
docker build --platform linux/amd64 -t hong/myseg:v1 .
docker save -o myseg_v1.tar hong/myseg:v1
```

- **이미지 이름 앞에 내 영어 이름을 붙여요(`hong/myseg:v1`).** 서버의 도커는 팀 전체가 하나를 같이 써서, 남과 같은 이름이면 서로 덮어써요.

- **`--platform linux/amd64`로 빌드해요.** Mac(Apple Silicon)은 기본이 arm64라서 서버에서 실행되지 않아요.
- **H200을 지원하는 PyTorch를 써요.** CUDA 12 이상으로 빌드한 PyTorch 2.1 이상이면 돼요(H200은 Hopper 세대, `sm_90`). 그보다 오래된 이미지에서는 `no kernel image is available` 오류가 나요. 서버 드라이버는 CUDA 13 이미지까지 돌려요. NVIDIA 공식 이미지(`nvcr.io/nvidia/pytorch`)의 최근 태그를 바탕 이미지로 쓰면 안전해요.
- 코드는 이미지에 넣지 않아도 돼요. 작업 폴더에 따로 올리면 고치기 쉬워요(5단계).

## 2. 올리기 (FileZilla)

| 무엇 | 서버의 어디로 |
|---|---|
| 코드 | `/app/autonomy_sw/<내 이름>/<프로젝트>` |
| 이미지 파일(`.tar`) | `/app/autonomy_sw/<내 이름>/images` |

- FileZilla는 홈 폴더(`~`)에서 열려요. 오른쪽 위 **원격 사이트** 칸에 `/app/autonomy_sw/<내 이름>` 을 입력하고 Enter 를 누른 뒤 올리세요. 홈의 `autonomy_sw` 폴더를 열어도 같은 곳이에요.
- 홈 폴더는 모두가 같이 쓰는 10 GB 공간이라 파일을 두지 않아요. 홈이 차면 모두의 접속 설정이 고장 나요.
- 큰 파일 전송이 끊기면 다시 올릴 때 **이어받기**를 고르세요.

## 3. 접속하고 이미지 들여오기

HIWARE(서버에 접속할 때 거치는 사내 접속 관리 시스템)로 접속하면 GPU 현황과 이름 목록이 나와요. 내 번호를 입력하세요.

```text
GPU 서버 (서버 이름)  팀원 모두가 공용 계정으로 써요. 이름을 고르면 GPU·컨테이너 옆에 이름이 보여요.
GPU별 사용자  (공용 계정이라 접속할 때 고른 이름으로 보여요)
GPU 배분           쓰는 사람       사용률 메모리 GB 컨테이너
0   자율주행매니저 -               0%     0/141     -
1   인지           김철수          97%    71/141    kcs-train
...
  이름을 고르세요(번호나 이름):
   1 홍길동   2 김철수   3 이영희
  > 1
[홍길동] 공용계정@gpu:/app/autonomy_sw/홍길동$
```

- 이름을 고르면 내 작업 폴더로 이동하고, 내 컨테이너와 GPU 옆에 이름이 붙어요.
- 명단에 이름이 없으면 관리자에게 등록을 요청하세요.
- 서버 2는 다른 팀과 같이 써요. 0~3번은 배분 칸에 "다른 팀" 으로 보이니 쓰지 말고, 4~7번만 써요.
- 한글 이름 목록이 깨져 보이면 PuTTY 설정 **Window → Translation → Remote character set** 을 `UTF-8` 로 바꾸세요. 번호로 고르면 글자가 깨져도 상관없어요.
- 이름을 고르지 않고 넘어갔으면 `exec bash -l` 로 다시 고를 수 있어요.

```bash
docker load -i images/myseg_v1.tar    # 이미지 들여오기
docker images                         # 확인
rm images/myseg_v1.tar                # 들여왔으면 파일은 지워서 공간을 비워요(다른 서버에서도 쓸 거면 지우지 말고 NAS로: "NAS에 보관하기")
```

`docker images` 목록에 `hong/myseg` `v1` 이 보이면 돼요.

## 4. 빈 GPU를 보고 컨테이너 만들기

`nvidia-smi` 출력 아래에 **GPU별 사용자** 표가 함께 나와요. 내 그룹(인지·판단처럼 GPU를 나눠 받은 단위, `서버_사용_규칙.md` 의 "GPU 배분")이나 공용 GPU 중에서 빈 것을 고르세요.

```bash
docker run -dit --name hong-seg \
  --gpus '"device=5"' --shm-size 32g -e HF_HUB_OFFLINE=1 \
  -v "$GPU_WS":/workspace -v /data/autonomy_sw:/data/autonomy_sw:ro \
  -w /workspace hong/myseg:v1 bash
```

| 옵션 | 뜻 |
|---|---|
| `-dit` | 컨테이너를 뒤에서 켜 둬요. 접속이 끊겨도 계속 켜져 있어요 |
| `--name hong-seg` | 컨테이너 이름. **영어·숫자·`-`만** 돼요. 남과 겹치지 않게 내 영어 이름을 앞에 붙여요. 내 이름표는 자동으로 붙어요 |
| `--gpus '"device=5"'` | 쓸 GPU 번호. 2장이면 `'"device=5,6"'` |
| `--shm-size 32g` | 데이터 로더(`num_workers`)가 멈추지 않게 공유 메모리를 넉넉히 줘요 |
| `-e HF_HUB_OFFLINE=1` | Hugging Face 에 접속하지 않게 해요(서버에는 인터넷이 없어요) |
| `-v "$GPU_WS":/workspace` | 내 작업 폴더(`/app/autonomy_sw/<내 이름>`)를 컨테이너 안 `/workspace`로 연결해요. `$GPU_WS` 는 접속할 때 고른 이름으로 정해져 있어서 그대로 붙여 넣으면 돼요 |
| `-v /data/autonomy_sw:/data/autonomy_sw:ro` | NAS(두 서버가 같이 보는 네트워크 저장소)의 팀 폴더(공용 데이터셋·모델). 컨테이너 안에서는 읽기만 돼요. 컨테이너 안에서도 서버와 같은 경로예요 |

`docker ps` 의 USER 칸에 내 이름, GPUS 칸에 고른 번호가 보이면 돼요.

남이 쓰는 GPU를 고르면 서버가 실행 전에 이렇게 경고하고 한 번 물어봐요.

```text
  [경고] GPU 1번은 지금 김철수 님이 쓰고 있어요. 같이 쓰면 메모리가 모자라 둘 다 멈출 수 있어요.
  내 그룹·공용의 빈 GPU: 5 6 7   (현황: nvidia-smi)
  그래도 실행할까요? [y/N]
```

- `--gpus all`이나 `--gpus 2`(장 수만)는 쓰지 마세요. 0번부터 잡아서 다른 사람과 겹쳐요.
- 컨테이너의 GPU는 만든 뒤에 바꿀 수 없어요. 바꾸려면 컨테이너를 새로 만들어요(안에서 설치한 것이 있으면 먼저 `docker commit`).

## 5. 컨테이너에서 실행하고 고치기

코드는 2단계에서 `/app/autonomy_sw/<내 이름>/<프로젝트>` 에 올렸어요. 컨테이너 안에서는 `/workspace/<프로젝트>` 예요. 아래 `myproj` 를 내 프로젝트 폴더 이름으로 바꾸세요.

```bash
docker exec -it -w /workspace/myproj hong-seg bash   # 프로젝트 폴더로 들어가기. 창을 여러 개 열어도 돼요
python train.py --epochs 1                           # 확인 삼아 실행
exit                                                 # 나와도 컨테이너는 계속 켜져 있어요
```

**접속이 끊겨도 계속 돌아야 하는 학습**은 `-d`로 뒤에서 실행하고, 기록은 파일로 봐요.

```bash
docker exec -d -w /workspace/myproj hong-seg bash -c 'python -u train.py > train.log 2>&1'
tail -f "$GPU_WS"/myproj/train.log                  # 서버에서 바로 볼 수 있어요(Ctrl+C로 나와도 학습은 계속)
docker exec hong-seg pgrep -af train.py              # 돌고 있는지 확인
docker exec hong-seg pkill -f train.py               # 이 학습만 멈추기(컨테이너는 그대로)
```

- `python -u` 를 붙여야 `print` 가 바로 기록 파일에 나와요. 빼면 몇 분씩 아무것도 나오지 않아 멈춘 것처럼 보여요.

화면을 붙였다 뗐다 하고 싶으면 `tmux`를 써도 돼요(`tmux` → `docker exec -it -w /workspace/myproj hong-seg python train.py` → `Ctrl+b` 누른 뒤 `d`, 다시 볼 때는 `tmux attach`). 사람마다 tmux가 따로라 남의 창과 섞이지 않아요. 접속할 때 같은 이름을 골라야 내 tmux가 보여요.

**간단한 수정**은 세 가지 방법 중 편한 것으로 해요. 모두 같은 파일을 고치는 거예요.

| 방법 | 어떻게 |
|---|---|
| 컨테이너 안에서 | `vim train.py` (이미지에 편집기가 있을 때) |
| 서버에서 | 컨테이너 밖 `/app/autonomy_sw/<내 이름>/<프로젝트>`에서 `micro train.py`(Ctrl+S 저장, Ctrl+Q 나가기) 또는 `vim` |
| 내 PC에서 | FileZilla에서 파일을 오른쪽 클릭 → **보기/편집**. 저장하면 서버로 다시 올릴지 물어봐요. 편집기는 FileZilla 설정에서 VS Code 등으로 바꿀 수 있어요 |

**패키지를 더 설치할 때**는 서버에 인터넷이 없으니 내 PC에서 받아 와요. 계속 쓸 패키지면 Dockerfile에 넣어 이미지를 다시 만드는 게 가장 깔끔해요.
급할 때는 내 PC에서 **같은 이미지로** 받아 올리면 Python 버전과 플랫폼이 저절로 맞아요.

```bash
# [내 PC] 같은 이미지 안의 pip 으로 받아 wheels 폴더에 모아요
docker run --rm --platform linux/amd64 -v "$PWD/wheels:/w" hong/myseg:v1 pip download --no-deps timm einops -d /w
```

- `--no-deps` 는 이미지에 이미 있는 torch 같은 큰 패키지를 다시 받지 않게 해요. 설치할 때 빠진 패키지 이름이 나오면 그것만 같은 방법으로 더 받아요.
- NVIDIA 공식 이미지(`nvcr.io/nvidia/pytorch`)는 torch 버전을 고정해 둬서, `--no-deps` 없이 받으면 실패할 수 있어요.

`wheels` 폴더를 FileZilla로 `/app/autonomy_sw/<내 이름>/wheels` 에 올린 뒤 컨테이너 안에서 설치해요.

```bash
pip install --no-index --find-links /workspace/wheels timm einops   # 컨테이너 안에서
```

- 컨테이너 안에서 설치한 것은 `docker stop`·`start`를 해도 남지만, `docker rm`하면 사라져요. 계속 쓰려면 `docker commit hong-seg hong/myseg:v2`로 이미지에 저장하세요.
- 컨테이너 안에서 만든 파일도 FileZilla로 바로 내려받고 지울 수 있어요. 단, 컨테이너 안에서는 root 로 실행해야 해요. `docker run --user` 를 쓰거나 Dockerfile 에 `USER` 를 넣으면 파일 주인이 달라져 FileZilla로 지울 수 없게 돼요. 이미 `USER` 가 들어간 이미지면 `docker run` 에 `--user 0` 을 붙이세요.

## 6. 결과 내려받기

FileZilla로 `/app/autonomy_sw/<내 이름>`에서 내려받아요. 서버에 오래 둘 결과는 내 PC 대신 NAS에 보관해도 돼요("NAS에 보관하기").

## 7. 다 쓰면

```bash
docker stop hong-seg      # GPU 놓기. 다시 쓸 때: docker start hong-seg
docker rm hong-seg        # 컨테이너 지우기
docker rmi hong/myseg:v1  # 이미지도 필요 없으면
```

GPU를 잡은 채로 12시간 동안 사용률이 0%면 알림이 와요. 다 쓴 컨테이너는 `docker stop`으로 놓아 주세요.
남의 컨테이너를 멈추거나 지우려 하거나, 팀 전체의 이미지·컨테이너를 한꺼번에 지우는 `docker ... prune` 을 실행하면 서버가 한 번 물어봐요.

## NAS에 보관하기

> NAS는 팀마다 나눠 받은 공간이 아니라 여러 팀이 각자 알아서 쓰는 곳이에요. 그래서 우리 팀은 **`/data/autonomy_sw`** 한 폴더에만 둬요. 그 밖에 폴더를 만들면 다른 팀도 볼 수 있어요. 1인당 몫 같은 나머지 규칙은 정하는 중이에요.

두 서버가 같이 보는 NAS(`/data`)의 우리 팀 폴더에 오래 둘 결과, 도커 이미지, 다른 서버로 옮길 파일을 둬요.
내 이름 폴더(`backup/<내 이름>`, `docker_images/<내 이름>`)는 관리자가 만들어 둬요. 공용 데이터셋·모델도 여기(`datasets/`, `models/`)에 있어요.

| 무엇 | 어디에 | 명령 (서버 화면에서) |
|---|---|---|
| 실험 결과·체크포인트 보관 | `backup/<내 이름>/` | `rsync -a /app/autonomy_sw/<내 이름>/runs/exp1 /data/autonomy_sw/backup/<내 이름>/` |
| 도커 이미지 보관 | `docker_images/<내 이름>/` | `docker save -o /data/autonomy_sw/docker_images/<내 이름>/myseg_v1.tar hong/myseg:v1`. 들여온 `.tar` 가 아직 있으면 `mv images/myseg_v1.tar /data/autonomy_sw/docker_images/<내 이름>/` 가 더 빨라요 |
| 다른 서버에서 같은 이미지 쓰기 | `docker_images/<내 이름>/` | 다른 서버에서 `docker load -i /data/autonomy_sw/docker_images/<내 이름>/myseg_v1.tar` |
| 서버 사이에 파일 옮기기 | `tmp_transfer/` | 한 서버에서 넣고 다른 서버에서 가져간 뒤 지워요(14일이 지나면 지워질 수 있어요) |

- **컨테이너 밖 서버 화면에서 옮겨요.** 컨테이너에는 팀 폴더가 읽기 전용으로만 연결돼 있어요.
- **공용 데이터셋은 `/data/autonomy_sw/datasets` 에서 바로 읽어요.** 작은 파일이 아주 많아서 읽기가 느리면 `/app/autonomy_sw/<내 이름>` 으로 복사해서 써도 돼요.
- **팀 폴더 밖에는 두지 않아요.** NAS는 다른 팀과 같이 써요.
- **데이터셋·모델을 새로 넣을 때는 자리만 지켜요.** 데이터셋은 `datasets/<데이터셋>/`, 모델은 `models/<만든 곳>/<모델>/` 에 둬요. 접근 PC에서 받은 것은 `docs/5_데이터셋.md`, `docs/6_모델.md` 의 스크립트로 넣으면 자리에 맞춰 넣어 줘요. 이미 있는 남의 폴더는 지우거나 덮어쓰지 않아요.
- `originals/` 는 관리자가 보관하는 설치 파일이라 읽기만 돼요. 남의 이름 폴더도 건드리지 않아요.
- 지운 파일은 되살리지 못할 수 있어요. 지우기 전에 한 번 더 확인하세요.
- 폴더별 사용량은 관리자가 주간 보고서로 봐요. 1인당 몫은 정해지면 알려 드려요.

| 컨테이너와 주인(USER), GPU | `docker ps` |
| 내 폴더 크기 | `du -sh /app/autonomy_sw/<내 이름>`, NAS는 `du -sh /data/autonomy_sw/*/<내 이름>` |

## 알림

서버가 10분마다 GPU와 디스크를 확인하고, 필요할 때만 알려 줘요. 멈추거나 지우지는 않아요.

| 알림 | 언제 | 얼마나 자주 |
|---|---|---|
| GPU 겹침 | 한 GPU를 두 사람 이상이 쓸 때 | 하루 한 번 |
| 놀고 있는 GPU | GPU를 잡고 12시간 내내 사용률 0% | 하루 한 번 |
| 디스크 | `/app`이 85%를 넘으면 많이 쓰는 3명에게 | 주 한 번 |
| 오래된 이미지 | 들여온 이미지를 30일 동안 안 쓰면 | 주 한 번 |

알림은 열어 둔 창에 한 줄로 뜨고, 다음에 접속할 때도 보여 줘요.

## Jupyter·TensorBoard·VS Code

지금 HIWARE에서는 PuTTY와 FileZilla만 돼요. 내 PC 브라우저로 Jupyter·TensorBoard를 보려면 **포트 연결(SSH 터널)** 이, VS Code로 서버에 접속하려면(Remote-SSH) 내 PC에서 서버로 **SSH 직접 접속** 이 허용돼야 해요. 둘 다 보안 담당자의 허락이 필요해서, 그 전까지는 이렇게 해요.

| 하고 싶은 것 | 지금 할 수 있는 방법 |
|---|---|
| TensorBoard | 로그 폴더(`runs`)를 FileZilla로 내려받아 내 PC에서 `tensorboard --logdir runs` |
| Jupyter | 노트북을 컨테이너 안에서 통째로 실행하고(이미지에 jupyter가 있어야 해요), 결과가 담긴 노트북을 내려받아요: `jupyter nbconvert --to notebook --execute --inplace 실험.ipynb` |
| VS Code | FileZilla **보기/편집**의 편집기를 VS Code로 정하면, 저장할 때 서버로 올라가요(5단계). 편집만 되고 터미널·디버깅은 안 돼요 |

## 자주 묻는 질문

| 상황 | 할 일 |
|---|---|
| 컨테이너 안에서 `torch.cuda.is_available()`가 False예요 | `docker run`에 `--gpus '"device=번호"'`를 빼먹었어요(만들 때 `--gpus 옵션이 없어서 GPU 없이 실행해요` 알림이 떠요). 컨테이너를 새로 만드세요 |
| `no kernel image is available` | H200을 지원하지 않는 PyTorch예요. 1단계의 PyTorch 조건을 보세요 |
| `exec format error` | arm64로 빌드한 이미지예요. `--platform linux/amd64`로 다시 빌드하세요 |
| 데이터 로더가 멈추거나 `bus error` | `--shm-size 32g`를 빼먹었어요 |
| `docker run`에서 `Conflict. The container name ... is already in use` | 같은 이름의 컨테이너가 있어요. `docker ps -a`로 보고 `docker start`하거나 이름을 바꾸세요 |
| `pip install`이 인터넷에 연결하려다 실패해요 | 서버에는 인터넷이 없어요. 5단계 "패키지를 더 설치할 때" 처럼 내 PC에서 받아 올려 `--no-index --find-links /workspace/wheels`로 설치하세요 |
| `/data/autonomy_sw/datasets`, `/data/autonomy_sw/models`에 파일을 못 써요 | 컨테이너 안에서는 읽기만 돼요. 컨테이너 밖 서버 화면에서 넣으세요. 서버 화면에서도 안 되면 관리자에게 알려 주세요 |
| 내 컨테이너가 `docker ps`의 USER 칸에 안 보여요 | 이름을 고르지 않고 접속했어요(만들 때 `이름을 고르지 않아` 알림이 떠요). `exec bash -l` 로 이름을 고른 뒤, 안에서 설치한 게 있으면 `docker commit` 으로 저장하고 컨테이너를 새로 만드세요 |
| `tmux attach` 가 `no sessions` 라고 해요 | tmux는 접속할 때 고른 이름마다 따로 있어요. tmux를 띄울 때와 같은 이름으로 접속했는지 보세요. 이름 없이 띄웠으면 이름 없이 접속해야 보여요 |
| `python` 기록 파일에 아무것도 안 나와요 | `python -u` 로 실행하세요(5단계) |
