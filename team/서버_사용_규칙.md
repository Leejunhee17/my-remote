# B200 서버 사용 규칙

B200 서버(GPU 8장)는 팀원 모두가 계정 하나(`shareduser`)로 같이 써요. 서버 입장에서는 모두가 같은 사람이라, **접속할 때 입력한 이름**과 **`b200` 명령**으로 서로를 구분해요.

## 규칙 6가지

| | 규칙 | 이렇게 하세요 | 안 지키면 |
|---|---|---|---|
| 1 | **접속하면 이름을 입력한다** | 접속하면 자동으로 물어봐요. 엑셀 '팀원' 시트의 이름을 입력해요 | GPU 사용이 '누군지 모름'(빨강)으로 표시되고, 관리자가 종료할 수 있어요 |
| 2 | **GPU는 `b200`으로 실행한다** | `b200 run auto python train.py` | 남이 쓰는 GPU는 `b200`이 막아 줘요. 직접 실행하다 겹치면 늦게 시작한 쪽을 관리자가 종료해요 |
| 3 | **그룹 GPU는 그 그룹이 먼저, 공용 GPU는 선착순** | 다른 그룹 GPU는 비어 있을 때만 빌려 쓰고, 그 그룹이 요청하면 30분 안에 비워요 | 30분이 지나면 관리자가 빌려 쓴 작업을 종료해요 |
| 4 | **파일은 내 작업 폴더에 둔다** | `/app/workspace/<이름>`. 접속하면 자동으로 이동해요. 끝난 결과는 NAS로 옮겨요 | 디스크가 80%를 넘으면 많이 쓰는 사람부터 정리를 요청해요 |
| 5 | **공용 폴더는 읽기만 한다** | 공용 패키지·데이터셋·모델 추가는 관리자에게 요청해요. 개인 패키지는 내 Python 환경에 설치해요 | 시스템이 쓰기를 막아요 |
| 6 | **도커 이미지는 들여온 사람이 관리한다** | `b200 image-load`로 들여오고, 30일 넘게 안 쓰면 `b200 rmi`로 지워요 | 보고서에 이름이 올라가고, 2주 더 지나면 관리자가 지워요 |

서버에서 `b200 rules`를 입력해도 같은 규칙이 나와요.

## 자주 쓰는 명령

| 하고 싶은 것 | 명령 |
|---|---|
| GPU 현황 보기(누가 어느 GPU를 쓰는지) | `b200` |
| 빈 GPU로 학습 시작 | `b200 run auto python train.py` (2장이면 `auto:2`, 번호를 정하려면 `1,2`) |
| 돌고 있는 내 작업 화면 보기 | `b200 attach` (나오기: `Ctrl+b` 누른 뒤 `d`) |
| 내 작업 목록 / 멈추기 | `b200 ps` / `b200 stop <세션>` |
| 도커로 실행 | `b200 docker auto <이미지> python train.py` (명령 없이 실행하면 컨테이너 셸) |
| 도커 이미지 들여오기 / 목록 | `b200 image-load /app/inbox/images/<이름>` / `b200 images` |
| 전체 도움말 | `b200 help` |

## 처음 접속하면

HIWARE로 B200 서버에 접속하면 아래처럼 지금 빈 GPU가 보이고 이름을 물어봐요.

```text
B200 서버  공용 계정이라 이름으로 사람을 구분해요. 규칙: b200 rules
  지금 빈 GPU: 0 2 4 6 7
  이름을 입력하세요 (예: 홍길동): 홍길동
[홍길동] shareduser@b200:/app/workspace/홍길동$
```

- 이름을 입력하면 내 작업 폴더로 이동하고, 명령 기록도 이름별로 따로 남아요.
- 이름을 잘못 입력했으면 접속을 끊고 다시 접속하세요.
- 명단에 이름이 없으면 관리자에게 등록을 요청하세요.

## GPU 쓰기

### GPU 배분

| GPU | 그룹 |
|---|---|
| 0 | 자율주행매니저 |
| 1, 2 | 인지 |
| 3, 4 | 판단 |
| 5, 6, 7 | 공용(선착순) |

배분은 엑셀 'GPU 배분' 시트와 같아요. 서버에서 `b200`을 입력하면 배분과 지금 쓰는 사람이 같이 보여요.

### `b200 run`이 해 주는 것

```bash
b200 run auto python train.py --epochs 100
```

- **GPU 고르기:** `auto`는 빈 GPU를 내 그룹 → 공용 → 다른 그룹 순서로 골라요. 남이 쓰는 GPU를 지정하면 실행을 막아요.
- **끊겨도 계속:** 작업을 tmux 안에서 돌려서, HIWARE 접속이 끊겨도 학습이 계속 돌아요.
- **기록:** 출력을 `/app/workspace/<이름>/logs/<세션>.log`에 저장해요.
- **표시:** 내 이름이 붙어서 `b200` 현황에 누가 쓰는지 보여요.

직접 `python train.py`로 실행해도 이름이 있는 접속이면 현황에 이름이 보여요. 하지만 남이 쓰는 GPU를 막아 주지 못하고, 접속이 끊기면 학습도 같이 멈춰요. 그래서 `b200 run`을 쓰는 게 규칙이에요.

## 폴더

| 위치 | 내용 | 권한 |
|---|---|---|
| `/app/workspace/<이름>` | 내 코드, 실험, 결과 (`~/workspace` 로도 보여요) | 쓰기 |
| `/app/shared/datasets` | 공용 데이터셋 | 읽기만 |
| `/app/shared/models/<만든 곳>/<모델>` | 공용 사전학습 모델 | 읽기만 |
| `/app/shared/wheels`, `venv`, `tools` | 공용 휠, 공용 Python 환경, 기초 프로그램 | 읽기만 |
| `/app/inbox/images/<이름>` | 내가 올린 도커 이미지 파일 | 쓰기 |
| 홈 `~` | 10 GB뿐이라 큰 파일은 두지 않아요 | 쓰기 |

## 내 Python 환경

인터넷이 없어도 공용 휠로 설치돼요.

```bash
/app/shared/tools/bin/python -m venv /app/workspace/<이름>/env
source /app/workspace/<이름>/env/bin/activate
pip install --no-index --find-links /app/shared/wheels -r /app/shared/lock.txt   # 공용 휠 전부
pip install --no-index --find-links /app/shared/wheels torch timm                # 필요한 것만
```

공용 환경을 그대로 쓰려면 `source /app/shared/venv/bin/activate`를 입력하세요. 공용 휠에 없는 패키지가 필요하면 관리자에게 요청하세요.

## 데이터셋과 모델 불러오기

서버에는 인터넷이 없어서, Hugging Face에 접속하지 않도록 설정이 미리 돼 있어요(`HF_HUB_OFFLINE=1`). 모델은 이름 대신 경로로 불러와요.

```python
from pathlib import Path
M = Path("/app/shared/models")

# transformers
from transformers import AutoModel
model = AutoModel.from_pretrained(M / "facebook/dinov3-vitl16-pretrain-lvd1689m")
model = AutoModel.from_pretrained(M / "nvidia/C-RADIOv4-H", trust_remote_code=True)   # 코드 파일도 같이 들어 있어요

# timm: 가중치 파일을 직접 지정해요
import timm
model = timm.create_model(
    "vit_large_patch16_dinov3.lvd1689m", pretrained=True,
    pretrained_cfg_overlay={"file": str(M / "timm/vit_large_patch16_dinov3.lvd1689m/model.safetensors")},
)

# 깊이: Depth Anything V2
from transformers import pipeline
depth = pipeline("depth-estimation", model=str(M / "depth-anything/Depth-Anything-V2-Metric-Outdoor-Large-hf"), device=0)
```

**GOOSE-M2F**(GOOSE로 학습한 Mask2Former)는 모델 구조가 함께 받은 코드에 있어요.

```python
import sys, torch
G = M / "XYZ9843/GOOSE-M2F"
sys.path.insert(0, str(G / "code"))
from src.model import GOOSEMask2Former   # 사용법: G / "code/instructions/instructions.md"
ckpt = torch.load(G / "best_model.pth", map_location="cpu", weights_only=False)
```

코드 안에서 `facebook/mask2former-swin-large-cityscapes-semantic` 을 이름으로 부르는 곳은 `str(M / "facebook/mask2former-swin-large-cityscapes-semantic")` 경로로 바꾸세요.
Depth Anything 3(`DA3METRIC-LARGE`, `DA3MONO-LARGE`)는 `depth_anything_3` 코드가 필요해요. 공용 환경에는 없으니 필요하면 관리자에게 요청하세요.

| 데이터셋 | 라벨 위치 (`/app/shared/datasets/` 아래) |
|---|---|
| GOOSE | `goose/goose_2d_*/labels/**/*_labelids.png` |
| GOOSE-Ex | `gooseEx/gooseEx_2d_*/labels/**/*_labelids.png` |
| RUGD | `RUGD/RUGD_annotations/*/*.png` |

있는 모델과 데이터셋은 엑셀 '모델 목록', '데이터셋 목록' 시트에서 볼 수 있어요.

## 도커

### 실행

```bash
b200 docker auto nvcr.io/nvidia/pytorch:25.10-py3 python train.py   # 학습(끊겨도 계속)
b200 docker auto nvcr.io/nvidia/pytorch:25.10-py3                   # 컨테이너 셸
```

- 내 작업 폴더는 컨테이너 안 `/workspace`, 공용 폴더는 `/app/shared`(읽기만)로 연결돼요.
- 이 서버의 도커는 관리자 권한 없이 도는 방식(rootless)이에요. 컨테이너 안에서 만든 파일도 내 작업 폴더에서 그대로 지우고 고칠 수 있어요.

### 이미지 들여오기

서버에는 인터넷이 없어서 이미지를 밖에서 만들어 올려야 해요. 방법은 세 가지예요.

| 방법 | 어디서 | 만드는 법 |
|---|---|---|
| 공개 이미지 받기 | 내 접근 PC(도커 없어도 됨) | `image_download.ps1` (아래) |
| 직접 빌드 | 도커가 있는 내 PC나 워크스테이션 | `docker build --platform linux/amd64 -t 이름:태그 .` → `docker save 이름:태그 \| gzip > 이름.tar.gz` |
| 서버에서 빌드 | B200 서버 | 들여온 이미지를 바탕으로 `docker build`. 단, `pip install` 은 아래처럼 공용 휠로 |

**공개 이미지 받기 (접근 PC):** 관리자에게 받은 `image_download.ps1` 파일 하나만 있으면 돼요.

```powershell
powershell -ExecutionPolicy Bypass -File .\image_download.ps1 nvcr.io/nvidia/pytorch:25.10-py3
```

바탕화면 `b200_images` 폴더에 `.tar`와 `.tar.sha256` 파일이 생겨요. 끊기면 같은 명령을 다시 실행하면 이어받아요. Docker Hub에서 받기 한도에 걸리면 Docker Hub 계정을 만들고 `-Login`을 붙이세요.

**서버에 올리고 들여오기:** 파일을 HIWARE로 `/app/inbox/images/<이름>/`에 올린 뒤 실행해요.

```bash
b200 image-load /app/inbox/images/<이름>
```

파일이 깨지지 않았는지 확인하고, 이미지를 들여온 뒤, 이미지 안 PyTorch가 B200에서 계산되는지까지 검사해요. 들여온 뒤에는 올린 파일을 지워 주세요.

### 직접 빌드할 때 꼭 지킬 것

- **`--platform linux/amd64`로 빌드해요.** Mac(Apple Silicon)은 기본이 arm64라 서버에서 실행되지 않아요.
- **B200을 지원하는 PyTorch를 써요.** CUDA 12.8 이상으로 빌드한 PyTorch 2.7 이상이어야 해요. 그보다 오래된 이미지는 계산할 때 `no kernel image is available` 오류가 나요. NVIDIA 공식 이미지(`nvcr.io/nvidia/pytorch`)의 최근 태그를 바탕으로 쓰면 안전해요.
- **서버에서 빌드할 때는 인터넷 대신 공용 휠을 써요.**

```dockerfile
FROM nvcr.io/nvidia/pytorch:25.10-py3
COPY wheels /wheels
RUN pip install --no-index --find-links /wheels timm einops && rm -rf /wheels
```

빌드 전에 필요한 휠을 작업 폴더로 복사해 두세요: `cp /app/shared/wheels/timm-* /app/shared/wheels/einops-* ./wheels/`

## 자주 묻는 질문

| 상황 | 할 일 |
|---|---|
| `GPU N 는 지금 ○○ 가 쓰고 있어요` | `b200`으로 빈 GPU를 확인하고 `auto`를 쓰세요 |
| 접속이 끊겼는데 학습이 살아 있나요? | `b200 run`으로 시작했다면 살아 있어요. `b200 attach`로 다시 보세요 |
| 현황에 내 작업이 `?`(빨강)로 보여요 | 이름 없이 접속해 실행한 거예요. 다시 접속해 이름을 입력하고 `b200 run`으로 실행하세요 |
| `/app/shared` 에 파일을 못 써요 | 공용 폴더는 읽기만 돼요. 추가가 필요하면 관리자에게 요청하세요 |
| 이미지 검사에서 `no kernel image` | B200을 지원하지 않는 PyTorch예요. 위 "직접 빌드할 때 꼭 지킬 것"을 보세요 |
| 그 밖에 막히면 | `b200 doctor`의 결과를 관리자에게 보내 주세요 |
