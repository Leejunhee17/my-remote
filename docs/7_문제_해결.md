# 문제 해결

파일을 받아 묶거나 서버에 설치하는 스크립트가 멈추거나 `[문제]` 를 보여 줄 때, 화면에 나온 메시지로 해결 방법을 찾는 문서예요.
팀원이 컨테이너를 쓰다가 막혔다면 `team/사용_안내.md` 의 "자주 묻는 질문" 을 보세요.

## 먼저 할 일

1. 화면의 `멈춤` 상자나 `[문제]` 줄에 적힌 **할 일** 을 하세요.
2. 같은 명령을 다시 실행하세요. 모든 스크립트는 다시 실행해도 돼요. 끝난 것은 건너뛰고, 받다 만 것은 이어서 받아요.
3. 그래도 안 되면 아래 표에서 메시지를 찾으세요.
4. 접근 PC(인터넷이 되는 윈도우 PC)에서 원인을 모르겠으면 `.\pc\check.ps1` 로 점검하세요. 결과 끝의 "고칠 것" 에 할 일이 모여요. 결과(`reports\pc_check_공유용_…txt`)를 git 으로 올리면 담당자가 읽어요(`docs/1_처음_설치.md` 의 "접근 PC 점검").

## 접근 PC에서 나는 문제

| 메시지 | 할 일 |
|---|---|
| `스크립트를 실행할 수 없습니다` | `-ExecutionPolicy Bypass` 가 빠졌어요. `docs/1_처음_설치.md` 의 명령을 그대로 복사해 실행하세요 |
| `파일을 찾을 수 없습니다` (`.\setup_pack.ps1` 등) | 스크립트는 `pc\` 폴더에 있어요. `.\pc\setup_pack.ps1` 처럼 실행하세요 |
| `uv가 없어요` | 설치한 뒤 PowerShell 창을 새로 여세요. 그래도 안 되면 `uv.exe` 를 `D:\gpu` 에 넣으세요 |
| `인터넷: … 접속 안 됨` | 회사망 문제(인증서 폐기 확인, 윈도우 프록시)는 스크립트가 스스로 우회해요. 그래도 안 되면 사내 IT에 프록시 주소를 물어 `.env` 에 `HTTPS_PROXY=http://프록시주소:포트` 를 적으세요 |
| `.env … 번째 줄을 읽지 못했어요` | `.env` 의 그 줄이 `이름=값` 모양이 아니에요. 설명을 적을 때는 줄 맨 앞에 `#` 을 붙이고, 값에 공백 뒤 `#` 이 들어가면 `"따옴표"` 로 감싸세요 |
| `모르는 작업이에요` | `.env` 의 `GPU_RUN` 이나 `-Run` 뒤에는 `setup`, `pkgs`, `docker`, `datasets`, `models` 만 쓸 수 있어요 |
| `링크가 만료됐거나 거절됐어요` | WildScenes 링크 목록은 유효 기간이 있어요. 포털에서 새로 받아 바로 같은 명령을 다시 실행하세요. 받은 파일은 건너뛰어요 |
| `Google Drive 접속 안 됨` | 접근 PC의 Drive 허용은 2026년 말까지예요. 그 뒤거나 아직 적용 전이면 Drive 데이터셋(RELLIS-3D, TAS500, GO)만 건너뛰고 나머지는 받아요. 사내 IT에 `drive.google.com`, `drive.usercontent.google.com` 허용을 확인하세요 |
| WildScenes에서 `CSIRO S3 저장소에 접속되지 않아요` | 포털(data.csiro.au)은 열려도 실제 파일 서버 `s3.data.csiro.au` 가 회사 프록시·방화벽에 막힌 경우예요. 사내 IT에 `s3.data.csiro.au` (포트 443) 허용을 요청하세요. 브라우저로는 링크가 받아지는데 스크립트만 안 되면 `pc\wildscenes_check.ps1` 을 실행해 결과를 올려 주세요(`docs/5_데이터셋.md` 의 "WildScenes 링크 목록으로 받기") |
| Google Drive에서 `403` | `.\pc\datasets_download.ps1 -DriveCheck` 로 이유를 보세요. 이유별 할 일은 `docs/5_데이터셋.md` 의 "Google Drive 데이터셋 받기" 에 있어요 |

## GPU 서버에서 나는 문제

| 메시지 | 할 일 |
|---|---|
| `올리는 중에 파일이 깨졌어요`, `체크섬이 맞지 않아요`, `올린 폴더에 빠진 파일이 있어요` | 설치 묶음(`.tar`)이면 묶음 파일을 NAS 의 `/data/autonomy_sw/inbox` 에 다시 올리고 `gpu fetch` 로 새로 복사한 뒤 다시 푸세요. 데이터셋·모델이면 화면에 나온 파일만 NAS inbox 의 같은 자리에 다시 올리고 같은 명령을 다시 실행하세요(된 것은 건너뛰어요) |
| `남은 공간이 … GB예요` | `gpu fetch` 에서 나오면 `/app` 이 모자란 거예요. 다 푼 `.tar` 파일과 `/app/inbox` 의 예전 복사본을 지우세요. 데이터셋·모델을 넣을 때 나오면 NAS 팀 폴더가 모자란 거예요. NAS inbox 에서 다 넣은 폴더를 지우거나, `/data/autonomy_sw` 의 안 쓰는 파일을 정리하거나, 서버 관리 팀에 물어보세요 |
| `unzip 명령이 없어요`, `서버 화면에서 쓰는 프로그램 중 없는 것: …` | OS 패키지가 빠졌어요. 기초 프로그램 묶음으로 설치하세요(`docs/1_처음_설치.md` 의 "2단계: 서버 기초 프로그램"). 없는 것만 설치해요 |
| `설치하려면 지워야 하는 패키지가 있어요: …` | 기초 프로그램을 설치하면 서버에 있던 패키지가 지워지는 경우예요. 아무것도 바꾸지 않고 멈췄어요. 화면의 패키지 이름을 서버 관리 팀에 보내 지워도 되는지 물어보세요. 기록 파일(`/var/log/gpu/pkgs_install_…log`)은 담당자에게 보내 주세요 |
| `설치할 수 없어요(의존 패키지가 맞지 않아요)` | 서버에 있는 패키지 버전이 묶음과 맞지 않아요. 접근 PC에서 `pkgs_pack.ps1` 을 다시 실행해 새 묶음(최신 업데이트 포함)을 만들어 올리세요. 그래도 나오면 기록 파일을 담당자에게 보내 주세요 |
| `이 묶음은 Ubuntu … 용인데 이 서버는 …이에요` | 서버 Ubuntu 버전이 묶음과 달라요. `pc\pkgs_pack.ps1` 의 `$Code` 를 서버 버전(`cat /etc/os-release` 의 `VERSION_CODENAME`)으로 고쳐 새 묶음을 만드세요 |
| `aria2c 를 준비하지 못했어요` | 받기 도구 aria2c 를 GitHub 에서 못 받았어요. 브라우저로 `https://github.com/aria2/aria2/releases/download/release-1.37.0/aria2-1.37.0-win-64bit-build1.zip` 을 받아 `D:\gpu\tools\aria2\aria2.zip` 으로 넣고 다시 실행하세요. 스크립트가 지문을 확인한 뒤 풀어서 써요 |
| `total length mismatch`(aria2c `errorCode=1`) | `expected` 가 작은 수, `actual` 이 큰 수면, 받다 만 파일을 이어받으려는데 사이트가 파일 대신 작은 웹 페이지(`expected` 크기)를 보낸 거예요. `actual` 은 받던 파일의 전체 크기예요. Google Drive 면 스크립트가 이어받는 위치로 다시 요청해 그 페이지를 확인해요. 한도 안내면 "하루 다운로드 한도" 로 알리고 받은 것은 그대로 둬요. 큰 파일 확인 페이지면 넘겨서 이어받아요. 그 밖의 페이지면 `datasets\drive_check\<파일 ID>.resume.html` 에 저장하니 그 파일을 보내 주세요 |
| `ORAD-3D 받지 못했어요`(ModelScope) | 브라우저로 `www.modelscope.cn` 이 열려도 스크립트는 막힐 수 있어요. 바로 위 modelscope 오류에서 이유를 찾으세요. ① `CERTIFICATE_VERIFY_FAILED`: 회사 보안 장비 인증서 문제예요. 스크립트가 윈도우 인증서 저장소를 쓰게 해 두었으니 `git pull` 뒤 다시 실행하세요. ② 다른 주소 이름이 나오면: 파일은 `www.modelscope.cn` 이 아니라 그 주소(파일 전송 서버)에서 받아요. `.\pc\check.ps1` 의 ModelScope 줄에 "실제 파일은 … 에서 받아요" 로 나오는 주소도 사내 IT에 허용을 요청하세요. ③ `pypi.org`·`files.pythonhosted.org`·`github.com` 이 나오면: 처음 한 번 modelscope 도구와 파이썬을 받는 단계에서 막힌 거예요. ④ `ProxyError`·`407`·연결 시간 초과: 파이썬은 브라우저의 자동 프록시 설정(PAC)과 윈도우 로그인 인증을 못 써요. `.env` 에 `HTTPS_PROXY=http://프록시주소:포트` 를 적으세요 |
| `CRYPT_E_NO_REVOCATION_CHECK`(curl 35) | 사내망에서 인증서 폐기 확인 서버에 닿지 않아 윈도우 curl 이 끊은 거예요(브라우저는 넘어가요). 그래서 스크립트는 curl 대신 aria2c 와 .NET 을 써요(`docs/5_데이터셋.md` 의 "WildScenes 링크 목록으로 받기"). 직접 curl 을 쓸 때 나오면 사내 IT에 CRL·OCSP 접속 허용을 요청하세요 |
| `gpu doctor` 에서 `GPU 계산 이상` 이나 오류가 나와요 | `QUICK=1 bash /app/inbox/check.sh` 를 실행해 드라이버와 NVLink 상태를 보고, `[문제]` 목록을 서버 관리 팀에 보내세요. 오류에 `802` 가 있으면 Fabric Manager 문제예요(HGX 보드일 때만. 지금 H200 NVL 은 해당 없어요) |
| 서버의 `sha256sum` 지문이 접근 PC 화면의 지문과 달라요 | 올리는 중에 깨졌거나 누군가 바꾼 거예요. **실행하지 마세요.** NAS inbox 와 `/app/inbox` 의 그 파일을 지우고 다시 올려 새로 복사하세요 |
| `root 말고 공용 계정으로 실행하세요` | 데이터셋·모델 넣기(4·5단계)는 사용자 몫이라 공용 계정으로 실행해요. root 로 넣으면 팀원이 고치거나 지울 수 없는 파일이 생겨요 |
| `… 에 쓸 수 없어요`(데이터셋·모델) | NAS 의 `datasets`·`models` 를 공용 계정이 쓸 수 없는 상태예요. 관리자에게 알려 주세요. 관리자는 1단계 `prepare.sh` 를 다시 실행하거나 `docs/8_NAS.md` 의 "폴더 구조" 를 보세요 |
| `이미 있는데 이 스크립트가 넣은 폴더가 아니에요` | NAS 의 `datasets`·`models` 에 같은 이름의 폴더가 원래 있어서, 덮어쓰지 않고 그 데이터셋·모델만 건너뛰었어요. 안을 확인하고 지우거나 이름을 바꾼 뒤 다시 실행하세요 |
| `/app이 잠기지 않았거나 /app/docker가 링크예요` | 1단계 준비를 먼저 하세요: `cd /app/inbox && bash prepare.sh`. 그다음 같은 명령을 다시 실행하세요 |
| `/app 을 다른 계정도 써요`, `/app 잠금 보류` | 서버 2처럼 다른 팀이 `/app` 에 폴더를 둔 경우예요. 서버 관리 팀, 다른 팀과 협의한 뒤 PuTTY 화면에서 `prepare.sh` 를 직접 실행해 `y` 로 진행하세요 |
| `쓸 수 없는 이름이라 건너뛰어요`, `gpu_alloc.txt에 없는 그룹이에요` | `/app/admin/team.txt` 의 이름에서 `-`, `/` 를 빼고, 그룹은 `gpu_alloc.txt` 의 그룹 이름과 글자까지 같게 고친 뒤 `admin_setup.sh` 를 다시 실행하세요 |
| `root로 실행하면 다른 계정이 쓰는 폴더는 측정하지 않아요` | `check.sh disk` 를 root 로 공용 계정 폴더에 대해 실행한 경우예요. 같은 디스크의 root 폴더에서 측정하세요: `bash /app/inbox/check.sh disk /app/inbox`. 공용 계정으로 실행하면 공용 계정 폴더도 잴 수 있어요 |
| `아래에 root·공용 계정이 아닌 계정의 것이 있어요` | `/app` 에 다른 계정(다른 팀일 수 있어요)의 폴더가 있어요. 화면의 `/app` 목록에서 주인을 보고, 1단계에서 `/app` 을 잠그기 전에 서버 관리 팀에 누구 것인지 확인하세요 |
| `root 말고도 고칠 수 있는 시스템 폴더가 있어요` | 설치 스크립트(root)가 쓸 폴더를 다른 계정도 고칠 수 있어요. 화면의 "서버 관리 팀에 요청할 것" 을 그대로 보내고, 고친 뒤 1단계를 하세요 |
| `공용 계정 홈에 보고서를 넣지 못해서` | `/etc/gpu/account` 가 없거나, 공용 계정 홈이 없거나, 홈에 같은 이름의 파일·링크가 있어 공용 계정이 덮어쓸 수 없는 경우예요. 화면에 나온 root 전용 폴더의 보고서를 보거나, 원인을 고친 뒤 다시 실행하세요 |
| `NAS에 지금 계정이 쓸 수 있는 폴더가 없어서` | 공용 계정으로 실행했는데 1단계 전이라 `/data/autonomy_sw/tmp_transfer` 가 아직 없는 거예요. 서버·NAS 상태는 그대로 봤어요. 두 서버에서 root 로 다시 실행하거나(`/data/tmp` 를 써요), 1단계 `prepare.sh` 뒤에 다시 실행하면 상대 서버 찾기와 속도까지 재요 |
| `라벨을 못 찾음` | 화면의 "지금 구조" 를 보고 `docs/5_데이터셋.md` 의 "라벨 위치" 대로 폴더를 옮기세요 |

## 그래도 안 되면

아래 기록 파일을 담당자에게 보내 주세요.

| 어디서 | 기록 파일 |
|---|---|
| 접근 PC | 먼저 `.\pc\check.ps1` 로 점검 결과를 올려요(마지막 실행의 멈춘 이유도 들어가요). 더 필요하면 `D:\gpu\setup\build.log`, `D:\gpu\pack_pkgs\build.log`, `D:\gpu\pack_docker\build.log`, `D:\gpu\datasets\download.log`, `D:\gpu\models\download.log` |
| GPU 서버 | `/app/admin/logs/` 에서 가장 최근 파일. 데이터셋·모델 넣기는 올린 곳(NAS 의 `inbox/datasets`, `inbox/models`)의 `.log`. 기초 프로그램·도커 설치는 `/var/log/gpu/`, 점검 보고서는 공용 계정의 홈(`check_report_…txt`), 주간 보고서는 `/app/state/reports/` |
