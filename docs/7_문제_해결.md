# 문제 해결

반입·설치 스크립트가 멈추거나 `[문제]` 를 보여 줄 때, 화면에 나온 메시지로 해결 방법을 찾는 문서예요.
팀원이 컨테이너를 쓰다가 막혔다면 `team/사용_안내.md` 의 "자주 묻는 질문" 을 보세요.

## 먼저 할 일

1. 화면의 `멈춤` 상자나 `[문제]` 줄에 적힌 **할 일** 을 하세요.
2. 같은 명령을 다시 실행하세요. 모든 스크립트는 다시 실행해도 돼요. 끝난 것은 건너뛰고, 받다 만 것은 이어서 받아요.
3. 그래도 안 되면 아래 표에서 메시지를 찾으세요.

## 접근 PC에서 나는 문제

| 메시지 | 할 일 |
|---|---|
| `스크립트를 실행할 수 없습니다` | `-ExecutionPolicy Bypass` 가 빠졌어요. `docs/1_처음_설치.md` 의 명령을 그대로 복사해 실행하세요 |
| `파일을 찾을 수 없습니다` (`.\setup_pack.ps1` 등) | 스크립트는 `pc\` 폴더에 있어요. `.\pc\setup_pack.ps1` 처럼 실행하세요 |
| `uv가 없어요` | 설치한 뒤 PowerShell 창을 새로 여세요. 그래도 안 되면 `uv.exe` 를 `D:\gpu` 에 넣으세요 |
| `인터넷: … 접속 안 됨` | 회사망 문제(인증서 폐기 확인, 윈도우 프록시)는 스크립트가 스스로 우회해요. 그래도 안 되면 사내 IT에 프록시 주소를 물어 `.env` 에 `HTTPS_PROXY=http://프록시주소:포트` 를 적으세요 |
| `.env … 번째 줄을 읽지 못했어요` | `.env` 의 그 줄이 `이름=값` 모양이 아니에요. 설명을 적을 때는 줄 맨 앞에 `#` 을 붙이고, 값에 공백 뒤 `#` 이 들어가면 `"따옴표"` 로 감싸세요 |
| `모르는 작업이에요` | `.env` 의 `GPU_RUN` 이나 `-Run` 뒤에는 `setup`, `docker`, `datasets`, `models` 만 쓸 수 있어요 |
| `WildScenes2d 폴더를 찾지 못했어요`, `접속 정보가 만료됐거나 막혔어요` | WildScenes 접속 정보는 약 48시간만 유효해요. 포털에서 새로 받아 같은 명령을 다시 실행하세요 |
| `Google Drive 접속 안 됨` | 접근 PC의 Drive 허용은 2026년 말까지예요. 그 뒤거나 아직 적용 전이면 Drive 데이터셋(RELLIS-3D, TAS500, GO)만 건너뛰고 나머지는 받아요. 사내 IT에 `drive.google.com`, `drive.usercontent.google.com` 허용을 확인하세요 |
| WildScenes에서 `CSIRO S3 저장소에 접속되지 않아요`, `curl 오류 56` | 포털(data.csiro.au)은 열려도 실제 파일 서버 `s3.data.csiro.au` 가 회사 프록시·방화벽에 막힌 경우예요. 화면에 `CONNECT tunnel failed, response 403` 이 있으면 프록시가 거절한 거예요. 사내 IT에 `s3.data.csiro.au` (포트 443) 허용을 요청하세요. 브라우저에서는 `https://s3.data.csiro.au/` 가 401·AccessDenied라도 뜬다면, 스크립트가 브라우저와 같은 프록시와 윈도우 로그인 인증을 자동으로 찾아 써요. 그래도 AWS CLI 단계에서 막히면 `docs/5_데이터셋.md` 의 "WildScenes 링크 목록으로 받기" 로 받으세요 |
| Google Drive에서 `403` | `.\pc\datasets_download.ps1 -DriveCheck` 로 이유를 보세요. 이유별 할 일은 `docs/5_데이터셋.md` 의 "Google Drive 데이터셋 받기" 에 있어요 |

## GPU 서버에서 나는 문제

| 메시지 | 할 일 |
|---|---|
| `올리는 중에 파일이 깨졌어요`, `올리는 중에 깨졌거나 빠진 파일이 있어요` | 화면에 나온 파일만 접근 PC에서 `/app/upload` 에 다시 올리고, `/app/inbox` 의 같은 자리에 복사하세요. 도커 묶음이라면 묶음 파일(`.tar`)을 다시 올려 복사한 뒤 다시 푸세요 |
| `남은 공간이 … GB예요` | `gpu fetch` 에서 나오면 `/app` 이 모자란 거예요. 다 푼 `.tar` 파일과 `/app/upload`·`/app/inbox` 의 예전 복사본을 지우세요. 데이터셋·모델 설치에서 나오면 NAS 팀 폴더가 모자란 거예요. `/data/autonomy_sw` 의 안 쓰는 파일을 정리하거나 서버 관리 팀에 물어보세요 |
| `unzip 명령이 없어요`, `서버 화면에서 쓰는 프로그램 중 없는 것: …` | OS 패키지가 빠졌어요. 화면에 나온 패키지 이름을 서버 관리 팀에 보내 설치를 요청하세요(`docs/1_처음_설치.md` 의 "서버에 설치해 달라고 할 패키지") |
| `gpu doctor` 에서 `GPU 계산 이상` 이나 오류가 나와요 | `QUICK=1 bash /app/inbox/check.sh` 를 실행해 드라이버와 NVLink 상태를 보고, `[문제]` 목록을 서버 관리 팀에 보내세요. 오류에 `802` 가 있으면 Fabric Manager 문제예요(HGX 보드일 때만. 지금 H200 NVL 은 해당 없어요) |
| 서버의 `sha256sum` 지문이 접근 PC 화면의 지문과 달라요 | 올리는 중에 깨졌거나 누군가 바꾼 거예요. **실행하지 마세요.** `/app/upload` 와 `/app/inbox` 의 그 파일을 지우고 다시 올려 새로 복사하세요 |
| `올린 폴더에 링크가 있어서 복사본을 지웠어요`, `안에 링크가 있어요(올린 폴더에 누가 넣었을 수 있어요)` | 올린 데이터셋·모델 폴더에 링크가 섞여 있어요. `/app/upload` 의 폴더를 지우고 접근 PC 폴더를 다시 올린 뒤 `/app/admin/bin/gpu fetch <이름>` 을 다시 실행하세요 |
| `체크섬 목록에 없는 파일 …개는 옮기지 않아요` | 접근 PC에서 받지 않은 파일이 올린 모델 폴더에 들어 있어요. 일부러 넣은 게 아니면 누가 넣었는지 확인하세요. 필요한 파일이면 접근 PC의 목록(`lists/models.txt`)으로 받아 다시 올리세요 |
| `/app이 아직 잠기지 않았어요`, `/app이 잠기지 않았거나 /app/docker가 링크예요` | 관리자 기본 설정을 먼저 하세요: `cd /app/inbox && bash admin_setup.sh`. 그다음 같은 명령을 다시 실행하세요 |
| `/app 을 다른 계정도 써요`, `/app 잠금 보류` | 서버 2처럼 다른 팀이 `/app` 에 폴더를 둔 경우예요. 서버 관리 팀, 다른 팀과 협의한 뒤 PuTTY 화면에서 `admin_setup.sh` 를 직접 실행해 `y` 로 진행하세요 |
| `쓸 수 없는 이름이라 건너뛰어요`, `gpu_alloc.txt에 없는 그룹이에요` | `/app/admin/team.txt` 의 이름에서 `-`, `/` 를 빼고, 그룹은 `gpu_alloc.txt` 의 그룹 이름과 글자까지 같게 고친 뒤 `admin_setup.sh` 를 다시 실행하세요 |
| `root로 실행하면 다른 계정이 쓰는 폴더는 측정하지 않아요` | `check.sh disk` 를 root 로 공용 계정 폴더에 대해 실행한 경우예요. 같은 디스크의 root 폴더에서 측정하세요: `bash /app/inbox/check.sh disk /app/inbox`. 공용 계정으로 실행하면 공용 계정 폴더도 잴 수 있어요 |
| `공용 계정 홈에 보고서를 넣지 못해서` | `/etc/gpu/account` 가 없거나, 공용 계정 홈이 없거나, 홈에 같은 이름의 파일·링크가 있어 공용 계정이 덮어쓸 수 없는 경우예요. 화면에 나온 root 전용 폴더의 보고서를 보거나, 원인을 고친 뒤 다시 실행하세요 |
| `NAS에 지금 계정이 쓸 수 있는 폴더가 없어서` | 공용 계정으로 실행했는데 1단계 전이라 `/data/autonomy_sw/tmp_transfer` 가 아직 없는 거예요. 서버·NAS 상태는 그대로 봤어요. 두 서버에서 root 로 다시 실행하거나(`/data/tmp` 를 써요), 1단계 `admin_setup.sh` 뒤에 다시 실행하면 상대 서버 찾기와 속도까지 재요 |
| `라벨을 못 찾음` | 화면의 "지금 구조" 를 보고 `docs/5_데이터셋.md` 의 "라벨 위치" 대로 폴더를 옮기세요 |

## 그래도 안 되면

아래 기록 파일을 담당자에게 보내 주세요.

| 어디서 | 기록 파일 |
|---|---|
| 접근 PC | `D:\gpu\setup\build.log`, `D:\gpu\pack_docker\build.log`, `D:\gpu\datasets\download.log`, `D:\gpu\models\download.log` |
| GPU 서버 | `/app/admin/logs/` 에서 가장 최근 파일. 도커 설치는 `/var/log/gpu/`, 점검 보고서는 공용 계정의 홈(`check_report_…txt`), 주간 보고서는 `/app/state/reports/` |
