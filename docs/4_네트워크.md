# 두 서버와 NAS 네트워크

서버 1과 서버 2 사이, 그리고 NAS까지 얼마나 빠른지 잰 결과와, 그 결과로 정한 파일 옮기는 방법이에요.
서버 이름·IP·NAS 주소 같은 사내 정보와 측정 원본 보고서는 이 저장소에 적지 않아요. 원본은 서버의 `/app/inbox/reports/` 에 남아요.
다시 측정하거나 나머지 항목을 측정할 때는 `check_network.sh` 를 써요. 이 스크립트는 설정을 아무것도 바꾸지 않아요.

## 측정 결과 (2026-10-28, 서버 1 → 서버 2)

| 구간 | 연결 | 잰 값 | 판단 |
|---|---|---|---|
| 서버 ↔ 서버 | 10 Gbps 이더넷 2장 묶음(bond), 왕복 0.06 ms 안팎 | 동시 연결 8개 **2.28 GB/s (18.3 Gbps)** | 20 Gbps 의 92%라 회선이 꽉 찬 값이에요. 같은 스위치에 붙어 있어요 |
| 서버 → NAS | InfiniBand 400 Gbps, NFSv3 over RDMA, `nconnect=24` | 파일 1개 쓰기 **1.82 GB/s**, 읽기 **4.3 GB/s** | 서버 사이 이더넷보다 읽기가 약 2배 빨라요. 동시에 여러 개를 쓰면 더 나올 수 있어요 |
| InfiniBand | NDR 400 Gbps 6포트 모두 `ACTIVE`. 2포트만 IP가 있어요(NAS 망) | 아직 측정 안 함 | IP 없는 4포트는 GPU 서버끼리 RDMA(NCCL) 용일 가능성이 커요 |

NAS는 서버에서 `/data` 로 보여요. 구조·권한·용량 계획은 `docs/9_NAS.md` 에 있어요.

## 정한 것

- **서버 사이로 큰 파일을 옮길 때는 NAS를 거쳐요.** 두 서버가 같은 NAS를 쓰니 옮길 필요 없이 한쪽이 쓰고 다른 쪽이 읽으면 돼요. 이더넷(2.3 GB/s, 한 연결은 1.2 GB/s 안팎)보다 빨라요.
- **데이터셋·모델 반입은 서버 한 대에만 올려요.** 접근 PC → 서버 1의 `/app/upload` → 확인·설치한 뒤 NAS의 팀 폴더에 복사 → 서버 2는 공용 계정으로 NAS에서 `/app/upload` 로 옮긴 뒤, 평소처럼 `/app/inbox` 로 복사해 지문을 확인하고 설치해요. HIWARE로 두 번 올리지 않아도 돼요. 폴더 구조와 명령은 `docs/9_NAS.md` 에 있어요.
- **학습 데이터는 각 서버의 `/app`(로컬 SSD)에 둬요.** 이미지처럼 작은 파일이 많으면 NAS는 파일을 여는 데 시간이 걸려요. NAS는 옮기기와 보관용으로 써요.
- `scp` 하나로는 이더넷 카드 하나(10 Gbps, 1.2 GB/s 안팎)까지만 나와요. 암호화 때문에 그보다 낮을 수도 있어요.

## 아직 안 잰 것

서버 2 정보, 로컬 SSD, NAS 동시 8개, IPoIB, 같은 InfiniBand 망인지, RDMA 속도는 아직 측정하지 않았어요. 아래 "전체 점검"을 두 서버에서 실행하면 모두 측정해요.
RDMA 속도가 400 Gbps 에 가까우면 두 서버를 묶어 학습할 수 있어요.

## 전체 점검

두 서버에서 각각 아래 한 줄만 실행하세요. 두 번째 서버는 10분 안에만 실행하면 돼요.

```bash
# [서버 1, 서버 2 각각] root
cd /app/inbox && bash check_network.sh all
```

| 하는 일 | 내용 |
|---|---|
| 상대 서버 찾기 | 같은 NAS(`/data/tmp/.b200_net`)에 서로의 주소를 적어 두고 상대 서버를 찾아요. IP를 적지 않아도 돼요 |
| 서버 사이 이더넷 | 양쪽이 동시에 보내고 받아요 |
| 서버 사이 InfiniBand(IPoIB) | 두 서버 모두 InfiniBand IP가 있으면 측정해요 |
| 서버 사이 RDMA | 같은 이름의 카드끼리(`mlx5_0`↔`mlx5_0` …) `ib_write_bw` 로 측정해요. 두 서버를 묶어 학습할 수 있는지 여기서 갈려요(400 Gbps 에 가까워야 정상) |
| 로컬 SSD, NAS | 파일 1개와 동시 8개. NAS 는 두 서버가 차례로 측정해요(동시에 측정하면 값이 반이 돼요) |
| InfiniBand 망 | 카드마다 어떤 서버·장비가 보이는지(`ibhosts`, root). 상대 서버가 보이면 같은 망이에요 |
| 보고서 | root 로 실행하면 `/app/inbox/reports/` 에 원본과 공유용 두 개가 생겨요. 공유용만 git 으로 올려요(아래 "결과 가져오기") |

- RDMA 는 양쪽에 `perftest`, 망 조회는 `infiniband-diags` 가 있어야 해요. 없으면 `[주의]` 를 남기고 나머지만 측정해요. 보통 InfiniBand 드라이버(DOCA·MLNX OFED)와 함께 설치돼 있어요.
- 상대 서버를 10분 안에 못 찾으면 그 서버만 측정해요. NAS 를 못 찾으면 `bash check_network.sh all <NAS 안 쓸 수 있는 폴더>` 로 적어 줘요.
- 쓰는 포트: 5201·5202(TCP), 18515~18520(RDMA 준비). 서버 사이 방화벽이 막으면 양쪽 모두 `PORT=다른번호` 를 앞에 붙여요.

## 결과 가져오기

서버 밖으로 결과를 꺼낼 수 있는 길은 git 뿐이라서, 점검 스크립트가 보고서를 두 개 만들어요.

| 파일(`/app/inbox/reports/`) | 내용 | git 으로 |
|---|---|---|
| `network_report_…txt`, `nas_report_…txt` | 원본. 서버 이름·IP·NAS 주소·계정이 그대로 있어요 | 올리지 않아요 |
| `network_공유용_…txt`, `nas_공유용_…txt` | 그 정보를 가린 사본. IP는 `IP-1`, `IP-2`(같은 IP는 같은 번호), 서버는 `서버(…p1)`, 계정·NAS 폴더 이름은 `공용계정`·`폴더1` 로 바뀌어요. InfiniBand 장비 이름은 빼고 개수만 남겨요 | 올려요 |

1. **공용 계정의 FileZilla로 공유용만 내려받아** 접근 PC의 `D:\b200\reports\` 에 넣어요.
2. **올리기 전에 한 번 열어 보세요.** 가려지지 않은 이름이 보이면 직접 지우세요.
3. 올려요. 처음 한 번은 아래 "처음 한 번" 을 먼저 해요.

```powershell
# [접근 PC] PowerShell
cd D:\b200
git pull
git add reports
git commit -m "점검 결과(공유용)"
git push
```

**처음 한 번:** 실수로 원본이나 사내 정보를 올리지 않게 커밋 검사를 켜요. 가릴 낱말 목록은 저장소에 올라가지 않는 `.git\info\b200-blocklist.txt` 에 적어요.

```powershell
# [접근 PC] PowerShell, 저장소를 받은 뒤 한 번
cd D:\b200
git config core.hooksPath .githooks
notepad .git\info\b200-blocklist.txt     # 서버 이름, 공용 계정 이름, NAS 주소, 팀 이름을 한 줄에 하나씩
```

- 커밋할 때 사내 IP처럼 보이는 숫자, 목록의 낱말, 원본 보고서(`_report_`), `.env` 파일, 토큰·키처럼 보이는 값이 있으면 커밋을 멈추고 그 줄을 보여 줘요(토큰은 앞부분만).
- 원본 보고서와 `.env` 는 `.gitignore` 에도 들어 있어서 `git add` 로는 올라가지 않아요.

## 항목별 점검

```bash
# [서버 A, B 각각] 네트워크 카드 종류·속도, NAS 연결 경로, 다른 서버까지 연결
bash /app/inbox/check_network.sh <다른 서버 IP>

# [서버 B] 받는 쪽을 먼저 켜요(2분 기다려요)
bash /app/inbox/check_network.sh listen
# [서버 A] 보내는 쪽(10초)
bash /app/inbox/check_network.sh send <서버 B IP>

# [각 서버] NAS 와 로컬 SSD 의 쓰기·읽기 속도(시험 파일 4 GB를 쓰고 지워요)
bash /app/inbox/check_network.sh disk <NAS 안에 쓸 수 있는 폴더>
bash /app/inbox/check_network.sh disk /app/inbox
```

로컬 SSD는 root 로 측정할 때 `/app/inbox` 처럼 root 폴더에서 측정해요. root 는 공용 계정이 쓰는 폴더(`/app/workspace`)는 측정하지 않고 멈춰요. 그 폴더의 시험 파일을 누가 링크로 바꿔치기하면 root 가 시스템 파일을 덮을 수 있어서예요.

## 결과 읽는 법

| 결과에서 볼 것 | 뜻 |
|---|---|
| 네트워크 카드의 속도 | 이론상 최대치예요. 100 Gbps 카드 ≈ 12.5 GB/s |
| InfiniBand·RoCE 항목이 `ACTIVE` | GPU 서버끼리 빠르게 주고받는 카드가 연결돼 있어요. 어디에 연결됐는지는 서버 관리 팀에 물어보세요 |
| "다른 서버"의 응답, SSH(22) | 두 서버가 직접 이어져 있는지 |
| `send`·`listen` 결과 | 실제 서버 사이 속도. `iperf3` 가 있으면 그것으로, 없으면 python 으로 측정해요(100 Gbps 이상에서는 낮게 나올 수 있어요) |
| `disk` 결과 | NAS 가 로컬 SSD보다 많이 느리면, 학습 데이터는 `/app` 에 두고 NAS 는 보관용으로 써요 |

두 서버가 연결돼 있지 않으면, 데이터셋·모델은 서버마다 접근 PC에서 따로 올리거나 NAS를 거쳐 옮겨요.
