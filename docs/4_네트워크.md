# 두 서버와 NAS 네트워크

서버 1과 서버 2 사이, 그리고 NAS까지 얼마나 빠른지 잰 결과와, 그 결과를 보고 정한 파일 옮기는 방법이에요.
서버 이름·IP·NAS 주소 같은 사내 정보와 측정 원본 보고서는 이 저장소에 적지 않아요. 원본은 서버의 `/app/inbox/reports/` 에 남아요.
다시 측정하거나 나머지 항목을 측정할 때는 `check_network.sh` 를 써요. 이 스크립트는 설정을 아무것도 바꾸지 않아요.

## 측정 결과 (2026-11-03, 두 서버에서 `check_network.sh all`)

공유용 보고서는 `reports/network_공유용_…txt` 에 있어요. 두 서버의 값이 거의 같아서 한쪽만 느린 문제는 없어요.

| 구간 | 연결 | 잰 값 | 판단 |
|---|---|---|---|
| 서버 ↔ 서버, 이더넷 | 10 Gbps 2장 묶음(bond, balance-rr) | 동시 연결 8개 **2.2~2.3 GB/s (18 Gbps)** | 20 Gbps 회선이 꽉 찬 값이에요 |
| 서버 ↔ 서버, IPoIB | InfiniBand 400 Gbps 포트의 IP | 동시 연결 8개 **21~29 GB/s (170~230 Gbps)** | 이더넷의 약 10배예요 |
| 서버 ↔ 서버, RDMA | NDR 400 Gbps 6포트 모두 `ACTIVE`. 2포트는 IP가 있고(NAS·IPoIB), 4포트는 없어요 | 아직 못 잼(`perftest` 없음) | IP가 없는 4포트는 GPU 서버끼리 RDMA(NCCL)로 주고받는 용도일 가능성이 커요 |
| 서버 → NAS, 파일 1개 | NFSv3 over RDMA, `nconnect=24` | 쓰기 **1.8~1.9 GB/s**, 읽기 **4.3 GB/s** | |
| 서버 → NAS, 동시 8개 | 같음. 두 서버가 차례로 쟀어요 | 쓰기 **12.6~12.8 GB/s**, 읽기 **11.0~11.5 GB/s** | 파일을 나눠 동시에 쓰면 7배 빨라져요 |
| 로컬 SSD `/app` (서버 1) | LVM | 파일 1개 쓰기 3.2 / 읽기 13.6 GB/s, 동시 8개 쓰기 3.6 / 읽기 22.8 GB/s | 쓰기는 NAS 동시 8개보다 느려요 |

NAS는 서버에서 `/data` 로 보여요. 구조·권한·용량 계획은 `docs/8_NAS.md` 에 있어요.

## 정한 것

- **서버 사이로 큰 파일을 옮길 때는 NAS를 거쳐요.** 두 서버가 같은 NAS를 쓰니까 한쪽이 쓴 파일을 다른 쪽이 읽으면 돼요. 여러 파일을 동시에 쓰고 읽으면 11~13 GB/s 가 나와요.
- **서버끼리 직접 보내야 하면 InfiniBand IP로 보내요.** 이더넷 IP로 보내면 10배 느려요. 다만 `scp`·`rsync`(ssh)는 암호화 때문에 연결 하나가 1 GB/s 안팎에서 막혀요. 여러 개를 동시에 돌려야 빨라져요.
- **데이터셋·모델은 NAS에 한 번만 설치하고 두 서버가 같이 읽어요.** 접근 PC → 서버 1의 `/app/upload` → 확인한 뒤 NAS 팀 폴더(`/data/autonomy_sw`)에 설치해요. 서버 2는 할 일이 없어요. 폴더 구조는 `docs/8_NAS.md` 에 있어요.
- **학습 데이터는 NAS에서 바로 읽어요.** 동시 읽기 11 GB/s 는 우리 GPU 12장이 데이터를 읽는 속도(초당 수 GB)보다 넉넉해요. 서버 메모리가 데이터셋보다 크면 두 번째 에폭부터는 메모리에서 읽어요. 다만 이미지처럼 작은 파일을 많이 여는 속도는 아직 안 쟀어요. 느리면 그 데이터셋만 각자 `/app/autonomy_sw/<이름>` 에 복사해 써요.
- **체크포인트는 여러 파일로 나눠 저장하면 NAS가 로컬 SSD보다 빨라요**(쓰기 12.8 GB/s 대 3.6 GB/s). 파일 하나로 저장하면 로컬 SSD가 더 빨라요(3.2 GB/s 대 1.8 GB/s).

## 아직 안 잰 것

- **작은 파일 읽기**: 지금까지는 4 GB 파일로만 쟀어요. 이미지 수만 장을 여러 프로세스가 동시에 열 때의 속도는 실제 학습에서 확인해요. 느리면 위 "정한 것" 대로 로컬로 복사해 써요.
- **RDMA 속도와 InfiniBand 망**: 두 서버에 `perftest`, `infiniband-diags` 가 없어서 못 쟀어요. 아래 "InfiniBand 도구" 를 보세요. RDMA 속도가 400 Gbps 에 가까우면 두 서버를 묶어 학습할 수 있어요.
- **서버 2의 로컬 SSD**: `/app` 주인이 root 가 아니라서 건너뛰었어요(root 는 남이 쓸 수 있는 폴더에서 재지 않아요). 1단계 `admin_setup.sh` 를 실행한 뒤 다시 재요.

## InfiniBand 도구

RDMA 속도(`ib_write_bw`, `perftest` 패키지)와 InfiniBand 망 조회(`ibhosts`, `infiniband-diags` 패키지)에 필요해요. 두 서버 모두에 있어야 해요.
관리자는 root 라서 직접 설치할 수 있지만, 서버가 인터넷이 안 돼서 패키지 파일을 구해 와야 해요.

- **가장 쉬운 방법: Ubuntu로 다시 설치할 때(2026-11-12) 함께 넣어 달라고 해요.** `docs/1_처음_설치.md` 의 "서버 관리 팀에 요청할 것" 에 넣어 두었어요. InfiniBand 드라이버 묶음(DOCA-OFED)을 설치하면 둘 다 들어 있어요.
- **그 전에(RHEL 9) 재고 싶으면** 아래 순서로 확인해요. 서버 관리 팀이 관리하는 서버이니 설치하기 전에 알려 두세요. Ubuntu로 다시 설치하면 사라져요.

```bash
# [서버 1, 서버 2 각각] root
dnf repolist                                  # 1) 쓸 수 있는 저장소(사내 미러)가 있으면: dnf install perftest infiniband-diags
ofed_info -s 2>/dev/null                      # 2) 버전이 나오면 DOCA·MLNX OFED 로 설치된 서버예요. 같은 버전 묶음 안에 두 RPM이 있어요
rpm -q rdma-core libibumad perftest           # 3) 둘 다 아니면 rdma-core 버전을 보고 같은 버전의 RPM을 구해 와요
```

- 3)이면 접근 PC에서 RHEL 9 호환 저장소(Rocky·Alma Linux 9)에서 `perftest` 와, **rdma-core 와 버전이 같은** `infiniband-diags` RPM을 받아요. `infiniband-diags` 는 rdma-core 와 함께 만드는 패키지라 버전이 다르면 설치되지 않아요.
- 받은 RPM은 다른 설치 파일처럼 `/app/upload` → `/app/inbox` 로 옮긴 뒤 설치해요: `dnf install --disablerepo='*' ./perftest-*.rpm ./infiniband-diags-*.rpm`. 모자란 패키지가 나오면 같은 버전으로 함께 받아요.

## 전체 점검

두 서버에서 각각 아래 한 줄만 실행하세요. 두 번째 서버에서는 첫 번째 서버에서 실행한 뒤 10분 안에만 실행하면 돼요.

```bash
# [서버 1, 서버 2 각각] root
cd /app/inbox && bash check_network.sh all
```

| 하는 일 | 내용 |
|---|---|
| 상대 서버 찾기 | 같은 NAS(`/data/tmp/.gpu_net`)에 서로의 주소를 적어 두고 상대 서버를 찾아요. IP를 직접 적지 않아도 돼요 |
| 서버 사이 이더넷 | 양쪽이 동시에 보내고 받아요 |
| 서버 사이 InfiniBand(IPoIB) | 두 서버 모두 InfiniBand IP가 있으면 측정해요 |
| 서버 사이 RDMA | 같은 이름의 카드끼리(`mlx5_0`↔`mlx5_0` …) `ib_write_bw` 로 측정해요. 두 서버를 묶어 학습할 수 있는지가 여기서 갈려요(400 Gbps 에 가까워야 정상) |
| 로컬 SSD, NAS | 파일 1개, 동시 8개로 측정해요. NAS 는 두 서버가 차례로 측정해요(동시에 측정하면 값이 반이 돼요) |
| InfiniBand 망 | 카드마다 어떤 서버·장비가 보이는지(`ibhosts`, root). 상대 서버가 보이면 같은 망이에요 |
| 보고서 | root 로 실행하면 `/app/inbox/reports/` 에 원본과 공유용 보고서 두 개가 생겨요. 공유용만 git 으로 올려요(아래 "결과 가져오기") |

- RDMA 측정에는 양쪽에 `perftest` 가, 망 조회에는 `infiniband-diags` 가 있어야 해요. 없으면 `[주의]` 를 남기고 나머지만 측정해요. 설치는 위 "InfiniBand 도구" 를 보세요.
- 상대 서버를 10분 안에 못 찾으면 그 서버만 측정해요. NAS 를 못 찾으면 `bash check_network.sh all <NAS 안 쓸 수 있는 폴더>` 처럼 폴더를 직접 적어 주세요.
- 쓰는 포트: 5201·5202(TCP), 18515~18520(RDMA 준비). 서버 사이 방화벽이 이 포트를 막으면 양쪽 모두 명령 앞에 `PORT=다른번호` 를 붙여요.

## 결과 가져오기

서버 밖으로 결과를 꺼낼 수 있는 길은 git 뿐이라서, 점검 스크립트가 보고서를 두 개 만들어요.

| 파일(`/app/inbox/reports/`) | 내용 | git 으로 |
|---|---|---|
| `server_report_…txt`, `network_report_…txt`, `nas_report_…txt` | 원본. 서버 이름·IP·NAS 주소·계정이 그대로 있어요 | 올리지 않아요 |
| `server_공유용_…txt`, `network_공유용_…txt`, `nas_공유용_…txt` | 그 정보를 가린 사본. IP는 `IP-1`, `IP-2`(같은 IP는 같은 번호), 서버는 `서버(…p1)`, 계정·NAS 폴더 이름은 `공용계정`·`폴더1` 로 바뀌어요. InfiniBand 장비 이름은 빼고 개수만 남겨요 | 올려요 |

1. **공용 계정의 FileZilla로 공유용만 내려받아** 접근 PC의 `D:\gpu\reports\` 에 넣어요.
2. **올리기 전에 한 번 열어 보세요.** 가려지지 않은 이름이 보이면 직접 지우세요.
3. git 으로 올려요. 처음이라면 아래 "처음 한 번" 을 먼저 하세요.

```powershell
# [접근 PC] PowerShell
cd D:\gpu
git pull
git add reports
git commit -m "점검 결과(공유용)"
git push
```

**처음 한 번:** 실수로 원본이나 사내 정보를 올리지 않게 커밋 검사를 켜요. 가릴 낱말 목록은 저장소에 올라가지 않는 `.git\info\gpu-blocklist.txt` 에 적어요.

```powershell
# [접근 PC] PowerShell, 저장소를 받은 뒤 한 번
cd D:\gpu
git config core.hooksPath .githooks
notepad .git\info\gpu-blocklist.txt     # 서버 이름, 공용 계정 이름, NAS 주소, 팀 이름을 한 줄에 하나씩
```

- 커밋할 때 사내 IP처럼 보이는 숫자, 목록의 낱말, 원본 보고서(`_report_`), `.env` 파일, 토큰·키처럼 보이는 값이 있으면 커밋을 멈추고 그 줄을 보여 줘요(토큰은 앞부분만).
- 원본 보고서와 `.env` 는 `.gitignore` 에도 들어 있어서 `git add` 로는 올라가지 않아요.

## 항목별 점검

```bash
# [서버 A, B 각각] 네트워크 카드 종류·속도, NAS 연결 경로, 다른 서버까지 연결
bash /app/inbox/check_network.sh <다른 서버 IP>

# [서버 B] 받는 쪽을 먼저 켜요(2분 기다려요)
bash /app/inbox/check_network.sh listen
# [서버 A] 보내는 쪽(10초)
bash /app/inbox/check_network.sh send <서버 B IP>

# [각 서버] NAS 와 로컬 SSD 의 쓰기·읽기 속도(시험 파일 4 GB를 쓰고 지워요)
bash /app/inbox/check_network.sh disk <NAS 안에 쓸 수 있는 폴더>
bash /app/inbox/check_network.sh disk /app/inbox
```

로컬 SSD를 root 로 측정할 때는 `/app/inbox` 처럼 root 폴더에서 측정해요. root 로 실행하면 공용 계정이 쓰는 폴더(`/app/autonomy_sw`)는 측정하지 않고 멈춰요. 그 폴더의 시험 파일을 누가 링크로 바꿔치기하면 root 가 시스템 파일을 덮어쓸 수 있기 때문이에요.

## 결과 읽는 법

| 결과에서 볼 것 | 뜻 |
|---|---|
| 네트워크 카드의 속도 | 이론상 최대치예요. 100 Gbps 카드 ≈ 12.5 GB/s |
| InfiniBand·RoCE 항목이 `ACTIVE` | GPU 서버끼리 빠르게 주고받는 카드가 연결돼 있어요. 어디에 연결됐는지는 서버 관리 팀에 물어보세요 |
| "다른 서버"의 응답, SSH(22) | 두 서버가 직접 이어져 있는지 |
| `send`·`listen` 결과 | 실제 서버 사이 속도. `iperf3` 가 있으면 그것으로, 없으면 python 으로 측정해요(TCP 값이라 RDMA 보다는 낮아요) |
| `disk` 결과 | NAS 동시 읽기가 학습에 필요한 속도보다 느리면, 자주 쓰는 데이터셋은 로컬(`/app/autonomy_sw/<이름>`)에 복사해 써요 |

두 서버가 연결돼 있지 않으면, 데이터셋·모델은 서버마다 접근 PC에서 따로 올리거나 NAS를 거쳐 옮겨요.
