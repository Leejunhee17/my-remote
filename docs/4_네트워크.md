# 두 서버와 NAS 네트워크

서버 1(server1, 서버1-IP)과 서버 2(server2, 서버2-IP) 사이, 그리고 NAS까지 얼마나 빠른지 잰 결과와, 그 결과로 정한 파일 옮기는 방법이에요.
다시 재거나 나머지 항목을 잴 때는 `check_network.sh` 를 써요. 이 스크립트는 설정을 아무것도 바꾸지 않아요.

## 측정 결과 (2026-10-28, server1 → server2)

| 구간 | 연결 | 잰 값 | 판단 |
|---|---|---|---|
| 서버 ↔ 서버 | `bond0` = 10 Gbps 이더넷 2장, 왕복 0.057 ms | 8줄기 **2.28 GB/s (18.3 Gbps)** | 20 Gbps 의 92%라 회선이 꽉 찬 값이에요. 같은 스위치에 붙어 있어요 |
| 서버 → NAS | InfiniBand 400 Gbps(`ib`), NFSv3 over RDMA, `nconnect=24` | 1줄기 쓰기 **1.82 GB/s**, 읽기 **4.3 GB/s** | 서버 사이 이더넷보다 읽기가 약 2배 빨라요. 여러 줄기면 더 나올 수 있어요 |
| InfiniBand | NDR 400 Gbps 6포트 모두 `ACTIVE`. 2포트만 IP(NAS망-IP·22, NAS 망) | 아직 안 잼 | IP 없는 4포트는 GPU 서버끼리 RDMA(NCCL) 용일 가능성이 커요 |

NAS(`NAS망-IP:/nas`, 서버에서는 `/data`)는 경로 모양으로 보아 Dell PowerScale(Isilon)이에요. 원본 기록은 이 문서 끝의 "원본 기록"에 있어요.

## 정한 것

- **서버 사이로 큰 파일을 옮길 때는 NAS를 거쳐요.** 두 서버가 같은 NAS를 쓰니 옮길 필요 없이 한쪽이 쓰고 다른 쪽이 읽으면 돼요. 이더넷(2.3 GB/s, 한 연결은 1.2 GB/s 안팎)보다 빨라요.
- **데이터셋·모델 반입은 서버 한 대에만 올려요.** 접근 PC → 서버 1의 `/app/upload` → 확인·설치한 뒤 NAS에 복사 → 서버 2는 NAS에서 `/app/inbox` 로 복사해 지문을 확인하고 설치해요. HIWARE로 두 번 올리지 않아도 돼요.
- **학습 데이터는 각 서버의 `/app`(로컬 SSD)에 둬요.** 이미지처럼 작은 파일이 많으면 NAS는 파일을 여는 데 시간이 걸려요. NAS는 옮기기와 보관용으로 써요.
- `scp` 하나로는 이더넷 카드 하나(10 Gbps, 1.2 GB/s 안팎)까지만 나와요. 암호화 때문에 그보다 낮을 수도 있어요.

## 아직 안 잰 것

서버 2 정보, 로컬 SSD, NAS 8줄기, IPoIB, 같은 InfiniBand 망인지, RDMA 속도는 아직 안 쟀어요. 아래 "한 번에 재기"를 두 서버에서 실행하면 모두 재요.
RDMA 속도가 400 Gbps 에 가까우면 두 서버를 묶어 학습할 수 있어요.

## 한 번에 재기

두 서버에서 각각 아래 한 줄만 실행하세요. 두 번째 서버는 10분 안에만 실행하면 돼요.

```bash
# [서버 1, 서버 2 각각] root
cd /app/inbox && bash check_network.sh all
```

| 하는 일 | 내용 |
|---|---|
| 짝 찾기 | 같은 NAS(`/data/tmp/.b200_net`)에 서로의 주소를 적어 두고 짝을 찾아요. IP를 적지 않아도 돼요 |
| 서버 사이 이더넷 | 양쪽이 동시에 보내고 받아요 |
| 서버 사이 InfiniBand(IPoIB) | 두 서버 모두 InfiniBand IP가 있으면 재요 |
| 서버 사이 RDMA | 같은 이름의 카드끼리(`mlx5_0`↔`mlx5_0` …) `ib_write_bw` 로 재요. 두 서버를 묶어 학습할 수 있는지 여기서 갈려요(400 Gbps 에 가까워야 정상) |
| 로컬 SSD, NAS | 1줄기와 8줄기. NAS 는 두 서버가 차례로 재요(동시에 재면 값이 반이 돼요) |
| InfiniBand 망 | 카드마다 어떤 서버·장비가 보이는지(`ibhosts`, root). 짝 서버가 보이면 같은 망이에요 |
| 보고서 | 실행한 폴더에 `network_report_<서버>_<시각>.txt`. 두 파일을 이 문서의 "원본 기록"에 붙여요 |

- RDMA 는 양쪽에 `perftest`, 망 조회는 `infiniband-diags` 가 있어야 해요. 없으면 `[주의]` 를 남기고 나머지만 재요. 보통 InfiniBand 드라이버(DOCA·MLNX OFED)와 함께 깔려 있어요.
- 짝을 10분 안에 못 찾으면 그 서버만 재요. NAS 를 못 찾으면 `bash check_network.sh all <NAS 안 쓸 수 있는 폴더>` 로 적어 줘요.
- 쓰는 포트: 5201·5202(TCP), 18515~18520(RDMA 준비). 서버 사이 방화벽이 막으면 양쪽 모두 `PORT=다른번호` 를 앞에 붙여요.

## 하나씩 재기

```bash
# [서버 A, B 각각] 네트워크 카드 종류·속도, NAS 연결 경로, 다른 서버까지 연결
bash /app/inbox/check_network.sh <다른 서버 IP>

# [서버 B] 받는 쪽을 먼저 켜요(2분 기다려요)
bash /app/inbox/check_network.sh listen
# [서버 A] 보내는 쪽(10초)
bash /app/inbox/check_network.sh send <서버 B IP>

# [각 서버] NAS 와 로컬 SSD 의 쓰기·읽기 속도(시험 파일 4 GB를 쓰고 지워요)
bash /app/inbox/check_network.sh disk <NAS 안에 쓸 수 있는 폴더>
bash /app/inbox/check_network.sh disk /app/workspace
```

## 결과 읽는 법

| 결과에서 볼 것 | 뜻 |
|---|---|
| 네트워크 카드의 속도 | 이론상 최대치예요. 100 Gbps 카드 ≈ 12.5 GB/s |
| InfiniBand·RoCE 항목이 `ACTIVE` | GPU 서버끼리 빠르게 주고받는 카드가 연결돼 있어요. 어디에 연결됐는지는 서버 관리 팀에 물어보세요 |
| "다른 서버"의 응답, SSH(22) | 두 서버가 직접 이어져 있는지 |
| `send`·`listen` 결과 | 실제 서버 사이 속도. `iperf3` 가 있으면 그것으로, 없으면 python 으로 재요(100 Gbps 이상에서는 낮게 나올 수 있어요) |
| `disk` 결과 | NAS 가 로컬 SSD보다 많이 느리면, 학습 데이터는 `/app` 에 두고 NAS 는 보관용으로 써요 |

두 서버가 연결돼 있지 않으면, 데이터셋·모델은 서버마다 접근 PC에서 따로 올리거나 NAS를 거쳐 옮겨요.
