# 처음 설치하기

새로 설치한 B200 서버를 이 문서 순서대로 준비하면, 팀원이 바로 접속해 도커로 학습을 돌릴 수 있는 상태가 돼요. 서버 2대 모두 같은 순서로 해요.

- 서버는 RHEL 9에서 **Ubuntu 24.04 LTS** 로 바꿔요(서버 관리 팀 확정). 반입 묶음은 Ubuntu 22.04 이상이면 그대로 써요.
- 설치하면서 무엇이 생기고 왜 그렇게 했는지는 `docs/3_구조와_보안.md` 에 있어요.

## 전체 흐름

| 단계 | 접근 PC (PowerShell, `D:\b200`) | 올릴 것 → `/app/upload` (공용 계정 FileZilla) | B200 서버 (root, `/app/inbox` 로 복사·지문 확인한 뒤) | 끝나면 확인할 것 |
|---|---|---|---|---|
| 0. 서버 점검 | 없음 | `server\check_server.sh`, `server\check_network.sh`, `server\check_nas.sh` | `bash /app/inbox/check_server.sh`, 두 서버에서 각각 `bash /app/inbox/check_network.sh all`, `bash /app/inbox/check_nas.sh` | `[문제]` 가 없어요 |
| 1. 관리자 기본 설정 | `.\pc\pack_build.ps1` | `pack\b200-pack.tar` | `cd /app/inbox && tar xf b200-pack.tar && bash admin_setup.sh` | `/app` 이 root 소유로 잠겨요 |
| 2. 기초 프로그램 | (1단계 묶음에 들어 있어요) | | `cd /app/inbox && bash pack_install.sh /app/shared` | 완료 상자에 "모두 정상" |
| 3. 도커 | `.\pc\docker_pack.ps1` | `pack_docker\b200-docker.tar` | `cd /app/inbox && tar xf b200-docker.tar && bash docker_install.sh` | "rootless로 동작해요" |
| 4. 데이터셋 | `.\pc\datasets_download.ps1` | `datasets` 폴더 | `bash /app/inbox/datasets/datasets_install.sh` | 데이터셋마다 라벨 수가 보여요 |
| 5. 사전학습 모델 | `.\pc\models_download.ps1` | `models` 폴더 | `bash /app/inbox/models/models_install.sh` | 모델마다 크기·라이선스가 보여요 |
| 6. 팀원 입장에서 확인 | | | 공용 계정으로 접속 | 이름 목록, "GPU별 사용자" 표, GPU 계산 |

- 접근 PC 명령 앞에는 모두 `powershell -ExecutionPolicy Bypass -File` 이 붙어요.
- 올린 파일을 root 가 들여오는 방법은 아래 "서버에 파일 올리기" 에 있어요. 단계마다 같은 방법이에요.
- 모든 명령은 여러 번 다시 실행해도 돼요. 끝난 것은 건너뛰고, 받다 만 것은 이어서 받아요.

## 시작하기 전에

### 서버 관리 팀에 요청할 것

| 항목 | 요청 내용 | 이유 |
|---|---|---|
| Ubuntu 버전 | 24.04 LTS(확정) | 묶음은 glibc 2.35 이상에 맞춰 만들어서 24.04(glibc 2.39)에서 그대로 써요 |
| NVIDIA 드라이버 | 580 이상, open 커널 모듈(예: `nvidia-driver-580-open`) | 최신 CUDA(13.0)로 만든 팀원 이미지도 돌아가요. B200은 open 커널 모듈만 지원해요 |
| Fabric Manager | 드라이버와 같은 버전의 `nvidia-fabricmanager` 와 `nvlsm` 설치, 서비스 켜기 | HGX B200 보드는 이게 없으면 CUDA가 GPU를 쓰지 못해요(오류 802) |
| Persistence mode | `nvidia-persistenced` 켜기 | GPU를 처음 쓸 때 몇 초씩 기다리지 않아요 |
| `/app` | 2 TB SSD를 `/app` 에 연결하기(주인은 root 그대로). **가능하면 `/app` 은 포맷하지 않기** | `/app` 이 남으면 데이터셋과 모델을 다시 올리지 않아도 돼요. 공용 계정 쓰기 권한은 필요 없어요. `admin_setup.sh` 가 `/app/workspace` 만 공용 계정에 줘요 |
| 서버 2 같이 쓰기 | 다른 팀이 서버 2에 어떤 계정으로 들어오는지, `/app` 을 같이 쓰는지 | 우리 팀은 서버 2의 GPU 4~7번만 써요. 다른 팀이 `/app` 에 폴더를 두고 있으면 `admin_setup.sh` 가 잠그기 전에 물어봐요 |
| 계정 | 팀원이 같이 쓰는 계정 하나, 이전과 같은 이름. sudo·docker 그룹은 넣지 않기 | 0단계에서 이 이름을 서버의 `/etc/b200/account` 에 한 번 적으면 모든 스크립트가 거기서 읽어요 |
| 네트워크 | 두 서버가 서로 연결돼 있는지, 어떤 카드(이더넷·InfiniBand)와 속도로 연결됐는지, NAS 연결 경로와 속도 | 데이터셋·모델을 한 번만 올리고 다른 서버로 옮길 수 있는지 정해요. `iperf3` 를 설치해 주면 속도를 더 정확히 재요 |

서버 관리 팀에 요청할 것은 위 목록뿐이에요. 나머지 설치는 관리자 root 계정으로 해요. HIWARE에서 root 는 PuTTY만 되고 FileZilla는 안 돼요. 파일은 공용 계정의 FileZilla로 올려요.

### 포맷하기 전에

- `/app` 을 포맷하는지 서버 관리 팀에 확인하세요.
- `/app` 도 포맷한다면 팀원들이 `/app/workspace` 의 실험 결과를 NAS에 옮겨 두게 하세요.
- 접근 PC의 `D:\b200\datasets`, `D:\b200\models` 폴더는 지우지 마세요. `/app` 이 지워지면 이 폴더를 그대로 다시 올리면 돼요.
  데이터셋은 OS와 상관없어서 다시 받을 필요가 없어요. 모델은 `models_download.ps1` 을 다시 실행하면 목록에서 빠진 예전 모델을 지우고 새 목록의 모델만 받아요.

### 접근 PC 준비

1. 접근 PC에 git, uv, micromamba 가 설치돼 있어야 해요.
2. 시작 메뉴에서 **PowerShell** 을 여세요(관리자 권한 필요 없음, PowerShell ISE 아님).
3. 저장소를 받으세요. 비공개 저장소라 처음 받을 때 GitHub 로그인 창이 떠요. 이미 받았다면 `cd D:\b200` 후 `git pull` 만 하면 돼요.

```powershell
# [접근 PC] PowerShell
cd D:\
git clone <저장소 주소> b200      # 주소: GitHub 저장소 페이지의 Code 버튼에 있는 https 주소
cd D:\b200
```

받는 데 몇 시간 걸릴 수 있어요. 노트북이면 전원을 연결하세요. 실행 중 절전은 스크립트가 막아요.
받은 결과는 `D:\b200` 의 `pack\`, `pack_docker\`, `datasets\`, `models\` 에 생겨요(git에는 올라가지 않아요).

저장소를 받은 뒤 한 번 커밋 검사를 켜세요. 사내 정보가 실수로 올라가지 않게 막아 줘요(`docs/4_네트워크.md` 의 "결과 가져오기" 의 "처음 한 번").

### 서버에 파일 올리기

root 는 FileZilla를 쓸 수 없어서, 설치 파일은 세 단계로 들여와요.

1. **공용 계정의 FileZilla로 `/app/upload` 에 올려요.**
2. **root 로 `/app/inbox` 에 새로 복사해요.**
3. **복사본의 지문(sha256)이 접근 PC 화면의 지문과 같은지 보고 나서 실행해요.**

`/app/upload` 는 공용 계정 폴더라 팀원 누구든 파일을 바꿀 수 있어요. root 가 실행하는 것은 root 만 고칠 수 있는 `/app/inbox` 의 복사본이고, 지문이 같으면 접근 PC에서 만든 것과 한 글자도 다르지 않아요.

| 올리는 것 | 접근 PC의 지문 | B200 서버(root): 복사하고 지문 보기 |
|---|---|---|
| 점검 스크립트 3개 | `Get-FileHash server\check_server.sh, server\check_network.sh, server\check_nas.sh` | `cp /app/upload/check_*.sh /app/inbox/ && sha256sum /app/inbox/check_*.sh` |
| `b200-pack.tar` | `pack_build.ps1` 끝에 나와요 | `cp /app/upload/b200-pack.tar /app/inbox/ && sha256sum /app/inbox/b200-pack.tar` |
| `b200-docker.tar` | `docker_pack.ps1` 끝에 나와요 | `/app/shared/bin/b200 fetch b200-docker.tar` |
| `datasets` 폴더 | `datasets_download.ps1` 끝에 나와요 | `/app/shared/bin/b200 fetch datasets` |
| `models` 폴더 | `models_download.ps1` 끝에 나와요 | `/app/shared/bin/b200 fetch models` |

- 지문은 64글자예요. 접근 PC는 대문자, 서버는 소문자로 보여 줄 수 있으니 글자만 같으면 돼요. 앞뒤 8글자씩 맞춰 봐도 충분해요.
- 접근 PC 스크립트는 지문을 `D:\b200\지문_기록.txt` 에도 날짜와 함께 쌓아 둬요. 업로드가 끝난 뒤나 다른 날 맞춰 볼 때 여기서 찾으세요.
- 끝 화면에 "B200 서버가 쓰지 않는 큰 파일" 이 나오면(받다 만 파일, 목록에서 뺀 모델) 그 파일은 빼고 올려도 돼요.
- **지문이 다르면 실행하지 마세요.** `/app/upload` 의 파일을 지우고 다시 올려 새로 복사하세요.
- 1단계(`admin_setup.sh`)부터는 `/app/shared/bin/b200 fetch <이름>` 이 복사와 지문 보기를 한 번에 해요. 올린 폴더에 링크가 섞여 있으면 복사본을 지우고 멈춰요. 링크가 있으면 지문을 본 뒤에 링크 너머를 바꿔치기할 수 있어서예요.
- 폴더(데이터셋·모델)는 `MANIFEST.sha256`(파일 목록과 체크섬)과 설치 스크립트를 이어 붙인 지문 하나만 봐요. 나머지 파일은 설치 스크립트가 `MANIFEST.sha256` 으로 하나하나 확인하고, 목록에 없는 파일은 옮기지 않아요.
- 큰 파일 전송이 끊기면 다시 올릴 때 **이어받기**를 고르세요. 설치가 끝나면 `/app/upload` 의 원본은 지워 공간을 비우세요.

|---|---|---|
| `[정상]` 초록 | 확인했어요 | 없어요 |
| `[주의]` 노랑 | 계속 진행하지만 알아 둘 내용이 있어요 | 메시지를 읽으세요 |
| `[문제]` 빨강 | 끝까지 진행하지만 고칠 것이 있어요 | 메시지에 적힌 할 일을 하세요 |

## 0단계: 서버 점검

`server\check_server.sh`, `server\check_network.sh`, `server\check_nas.sh` 세 파일만 올려 실행하세요. 세 파일은 서버 설정을 바꾸지 않아요.
처음에는 올릴 폴더가 없으니 root 로 먼저 만드세요(1단계부터는 `admin_setup.sh` 가 맞춰요).
`/app` 을 포맷하지 않아 예전 것이 남아 있으면 누가 링크를 심어 뒀을 수 있어서, 먼저 확인하고 만들어요.

```bash
# [B200 서버] root, 처음 한 번
mkdir -p /etc/b200 && echo <계정이름> > /etc/b200/account   # <계정이름> 을 실제 공용 계정 이름으로 바꿔요(< > 도 지워요)
chmod 644 /etc/b200/account && id "$(cat /etc/b200/account)"   # uid=... 가 나오면 맞게 적은 거예요
ls -ld /app /app/inbox /app/upload                   # /app·inbox 주인이 root 가 아니거나 inbox·upload 가 링크(->)면 멈추고 아래를 보세요
mkdir -p /app/inbox /app/upload && chown -h root:root /app/inbox && chmod 755 /app/inbox && chown -h "$(cat /etc/b200/account):" /app/upload
```

- `/app` 주인이 root 가 아니면 공용 계정이 그 사이에 링크를 바꿔 넣을 수 있어요. 다른 계정 폴더가 없으면 `chown root:root /app && chmod 755 /app` 으로 먼저 잠그세요. 서버 2처럼 다른 팀 폴더가 있으면 그 팀과 정한 뒤에 하세요.
- `inbox` 나 `upload` 가 링크면 `rm /app/inbox`(링크만 지워요)로 지운 뒤 다시 하세요.
- `id` 줄에서 `no such user` 가 나오면 계정 이름을 잘못 적은 거예요. 첫 줄을 고쳐 다시 하세요.
- 오래 걸리는 명령(`check_network.sh all`, `b200 fetch`, 설치 스크립트)은 `tmux` 안에서 실행하세요. HIWARE 접속이 끊겨도 계속 돌아요(`tmux` → 명령 → 끊기면 다시 접속해 `tmux attach`). 기초 프로그램을 설치하기 전(0·1단계)에는 서버에 tmux 가 없으면 그냥 실행해요. 끊기면 같은 명령을 다시 하면 돼요.

세 파일을 `/app/upload` 에 올리고, 위 "서버에 파일 올리기" 대로 `/app/inbox` 에 복사해 지문을 확인한 뒤 실행하세요.

```bash
# [B200 서버] root
cp /app/upload/check_*.sh /app/inbox/ && sha256sum /app/inbox/check_*.sh
bash /app/inbox/check_server.sh
bash /app/inbox/check_network.sh all                 # 두 서버에서 각각: 서버 사이·NAS·SSD 속도까지 한 번에
bash /app/inbox/check_nas.sh                         # 두 서버에서 각각: NAS 용량·권한·계정 번호
```

`check_server.sh` 는 운영체제, glibc, 공용 계정, 드라이버, GPU 8장, NVLink Fabric, `/app` 주인과 SSD 여부, 설치에 필요한 기본 명령을 확인해요.

- **정상이면** 마지막에 "모두 정상" 이 나와요.
- **`[문제]` 가 있으면** 화면 끝의 "서버 관리 팀에 요청할 것" 목록을 그대로 보내고, "관리자가 직접 할 것" 은 직접 하세요.
- 네트워크·NAS 보고서는 `/app/inbox/reports/` 에 원본과 공유용 두 개가 남아요. 공유용만 git 으로 올려요(`docs/4_네트워크.md` 의 "결과 가져오기").
- 네트워크 결과를 읽는 방법은 `docs/4_네트워크.md`, NAS 결과로 정할 것은 `docs/9_NAS.md` 에 있어요.

## 1단계: 묶음 만들기와 관리자 기본 설정

접근 PC에서 묶음을 새로 만드세요. 묶음에는 기초 프로그램과 서버 설치 스크립트(`admin_setup.sh`, 도우미 등)가 들어 있고, glibc 기준이 2.35로 올라가요.

```powershell
# [접근 PC] PowerShell
cd D:\b200
git pull
powershell -ExecutionPolicy Bypass -File .\pc\pack_build.ps1
```

RHEL 때 받아 둔 `D:\b200\pack` 폴더는 지우지 않아도 돼요. 스크립트가 버전이 같은 파일은 다시 쓰고, 새 목록에 없는 예전 파일과 이제 쓰지 않는 공용 휠(`wheels`)은 지운 뒤 필요한 것만 새로 받아요. 묶음 파일(`b200-pack.tar`)도 매번 새로 만들어요.

`pack\b200-pack.tar` 를 `/app/upload` 에 올리세요. root 로 복사해 지문을 확인한 뒤, 묶음 안의 `admin_setup.sh` 를 **맨 먼저** 실행하세요.

```bash
# [B200 서버] root
cp /app/upload/b200-pack.tar /app/inbox/ && sha256sum /app/inbox/b200-pack.tar   # 접근 PC 화면의 지문과 같은지
cd /app/inbox && tar xf b200-pack.tar && bash admin_setup.sh
```

`admin_setup.sh` 가 하는 일이에요.

- `/app`, `/app/shared`, `/app/inbox` 를 root 만 고칠 수 있게 잠그고, `/app/upload` 는 공용 계정 폴더로 맞춰요.
- 공용 계정에 관리자 권한(sudo, docker 그룹)이 없는지 확인만 해요.
- 접속할 때 이름을 고르게 하는 설정, `docker`·`nvidia-smi` 도우미, 10분마다 도는 정기 점검을 설치해요.
- GPU 배분 파일(`/app/shared/gpu_alloc.txt`)이 없으면 서버 번호를 물어보고 만들어요. **1** = 우리 팀만 쓰는 서버, **2** = 다른 팀과 같이 쓰는 서버(0~3번 다른 팀). 서버 이름 끝이 `p2` 면 Enter 기본값이 2예요. 잘못 고르면 다른 팀 GPU 경고가 빠지고, 서버 2인데도 드라이버 버전을 고정해요. 그래서 꼭 확인하고 답하세요.
- 예전에 공용 계정으로 만든 `/app/shared` 가 있으면 데이터셋·모델과 명단·배분·알림 설정만 남기고, 기초 프로그램 같은 실행 파일은 `/app/.shared_old_<날짜>` 로 치워요. 공용 계정이 바꿔 둔 프로그램을 root 가 실행하지 않게 하려는 거예요. 기초 프로그램은 2단계에서 다시 설치해요.

**맨 먼저 하는 이유:** 잠그기 전에 root 로 설치하면, 공용 계정이 `/app` 에 심어 둔 링크를 따라 root 가 시스템 폴더에 쓸 수 있어요. 그래서 다른 설치 스크립트는 `/app` 이 잠겼는지 확인하고, 아니면 멈춰요.

끝나면 `/app/shared/team.txt` 에 팀원 `이름 그룹` 을 적고 한 번 더 실행하세요. 팀원마다 작업 폴더(`/app/workspace/<이름>`)가 생겨요.

## 2단계: 기초 프로그램

1단계 묶음으로 서버 화면에서 쓰는 명령(tmux, nvtop, rsync 등)을 설치해요. Python 패키지는 팀원이 도커 이미지에 넣어 오므로 공용으로 설치하지 않아요.

```bash
# [B200 서버] root
cd /app/inbox && bash pack_install.sh /app/shared
```

`/app/shared` 가 포맷 전 그대로 남아 있다면, 기초 프로그램을 한 번 새로 설치하는 것을 권해요.

```bash
# [B200 서버] root
cd /app/inbox && B200_REBUILD_TOOLS=1 bash pack_install.sh /app/shared
```

들어 있는 명령과 목록을 바꾸는 방법은 `docs/5_기초프로그램.md` 에 있어요.

## 3단계: 도커

```powershell
# [접근 PC] PowerShell
cd D:\b200
powershell -ExecutionPolicy Bypass -File .\pc\docker_pack.ps1
```

`pack_docker\b200-docker.tar` 를 `/app/upload` 에 올리고, root 로 복사해 지문을 확인한 뒤 설치하세요.

```bash
# [B200 서버] root
/app/shared/bin/b200 fetch b200-docker.tar      # 새로 복사하고 지문을 보여 줘요. 접근 PC 화면의 지문과 같은지
cd /app/inbox && tar xf b200-docker.tar && bash docker_install.sh
```

도커 데몬은 root 가 아니라 공용 계정 권한으로 돌아요(rootless). 컨테이너 안에서 무엇을 해도 서버 root 권한은 얻지 못해요.

## 4·5단계: 데이터셋과 모델

- `/app` 이 남아 있으면 할 일이 없어요. 0단계 점검 화면에 "예전 데이터셋이 남아 있다" 가 나와요.
- `/app` 이 지워졌으면 접근 PC에서 다시 받지 않고, 있는 `datasets`, `models` 폴더를 `/app/upload` 에 통째로 올린 뒤 설치 스크립트만 실행하면 돼요.
- 접근 PC의 지문은 `D:\b200\지문_기록.txt` 에 남아 있어요. 없으면 `datasets_download.ps1`, `models_download.ps1` 을 다시 실행하면 끝에 나와요(받은 것은 건너뛰어 금방 끝나요).

```bash
# [B200 서버] root
/app/shared/bin/b200 fetch datasets             # 접근 PC 화면의 지문과 같은지
bash /app/inbox/datasets/datasets_install.sh

/app/shared/bin/b200 fetch models
bash /app/inbox/models/models_install.sh
```

- 처음 받는 방법과 목록은 `docs/6_데이터셋.md`, `docs/7_모델.md` 에 있어요.
- **서버 2도 설치할 거면, 서버 1에서 설치가 끝난 뒤 `/app/inbox` 의 폴더를 지우기 전에 NAS에 보관하세요.** 서버 2는 HIWARE로 다시 올리지 않고 NAS에서 가져와요. 명령은 `docs/9_NAS.md` 의 "쓰는 법" 에 있어요(묶음 파일 `.tar` 도 같은 방법이에요).

## 6단계: 팀원 입장에서 확인

공용 계정으로 접속해 세 가지를 확인하세요.

1. 이름 목록이 나오고, 번호를 고르면 `/app/workspace/<이름>` 으로 이동해요.
2. `nvidia-smi` 아래에 "GPU별 사용자" 표가 붙어요. 서버 2는 0~3번이 "다른 팀" 으로 보여요.
3. `b200 doctor <PyTorch 이미지>` 에서 "보이는 GPU 1장 / GPU 계산 정상" 이 나와요. 서버에는 아직 이미지가 없으니, 팀원 안내(`team/사용_안내.md`)의 1~3단계대로 PyTorch 이미지 하나를 올려 공용 계정으로 `docker load` 하세요(예: 내 PC에서 `docker pull nvcr.io/nvidia/pytorch:<최근 태그>` → `docker save`). 드라이버·NVLink Fabric 이 실제로 GPU 계산까지 되는지는 여기서 처음 확인해요. 서버 2에서는 다른 팀 GPU를 피해 우리 GPU(4번)로 시험해요.

여기까지 되면 팀원에게 `team/` 폴더의 자료를 주세요.
