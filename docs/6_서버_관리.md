# 서버 관리 (관리자 전용)

공용 계정 하나(`shareduser`)로 여럿이 쓰는 B200 서버를 root 계정으로 관리하는 방법이에요. 팀원에게 보여 줄 규칙은 `team/` 에 따로 있어요.

## 구조 한눈에

| 누가 | 계정 | 할 수 있는 것 |
|---|---|---|
| 팀원 | `shareduser`(HIWARE 경유, 공용) | `/app/workspace`, `/app/inbox/images` 쓰기, `b200` 명령, rootless 도커 |
| 관리자 | root(HIWARE 경유, 나만) | 전부. 공용 폴더·시스템 설정·도커 서비스 |

`shareduser` 에는 sudo 와 docker 그룹을 주지 않아요. HIWARE가 `sudo` 명령을 막지 않기 때문에, 계정 쪽에서 권한이 없는 것이 유일한 방어선이에요. `admin_setup.sh` 가 실행할 때마다 확인하고 빼요.

| 장치 | 무엇을 막거나 돕나 | 만드는 스크립트 |
|---|---|---|
| 공용 폴더 잠금(`/app/shared` root 소유) | 실수로 공용 휠·데이터셋·모델을 지우거나 바꾸는 것 | `admin_setup.sh` |
| 접속 때 이름 묻기(`/etc/profile.d/b200.sh`) | 사람 구분. 프로세스 환경에 `B200_USER` 가 따라가서 GPU 사용자가 보여요 | `admin_setup.sh` |
| `b200 run`·`b200 docker` | 남이 쓰는 GPU 실행 거절, 다른 그룹 GPU 사용 경고, tmux 로 끊김 방지 | `server/bin/b200` |
| rootless 도커(`b200-docker` 서비스) | 컨테이너로 root 권한을 얻는 길을 막음. 데몬과 설정은 root 만 고침 | `docker_install.sh` |
| 5분 기록 + 매일 보고서 | 사람별 GPU 시간, 누군지 모르는 GPU 사용, 디스크, 오래된 이미지, GPU 오류 | `admin_setup.sh`(cron) |

## 처음 설정 순서

`docs/5_우분투_재설치.md` 의 순서를 따르세요. 요약하면 이래요.

1. `check_server.sh` 로 서버 점검
2. root 로 `pack_install.sh /app/shared`
3. root 로 `admin_setup.sh` → `/app/shared/team.txt` 에 팀원을 적고 한 번 더 실행
4. root 로 `docker_install.sh`
5. root 로 `datasets_install.sh`, `models_install.sh`
6. 공용 계정으로 접속해 이름을 묻는지, `b200` 현황이 나오는지, `b200 doctor` 가 정상인지 확인

## 팀원과 GPU 배분 바꾸기

| 할 일 | 서버 (root) | 엑셀 (`team/서버_사용_규칙.xlsx`) |
|---|---|---|
| 팀원 추가 | `/app/shared/team.txt` 에 `이름 그룹` 한 줄 → `bash admin_setup.sh`(작업 폴더 생성) | '팀원' 시트에 같은 내용 |
| 팀원 삭제 | `team.txt` 에서 줄 삭제. 작업 폴더는 NAS로 옮긴 뒤 지워요 | '팀원' 시트에서 삭제 |
| GPU 배분 변경 | `/app/shared/gpu_alloc.txt` 수정 | 'GPU 배분' 시트 수정 |

- 이름에는 `-`, `/`, 띄어쓰기를 쓸 수 없어요(작업 이름이 `이름-날짜` 형식이에요).
- 그룹 이름은 `gpu_alloc.txt` 의 그룹 이름과 글자까지 같아야 해요.
- `team.txt` 가 비어 있으면 아무 이름이나 받아요. 처음 설정할 때만 쓰는 상태예요.

## 매일 볼 것

```bash
# [B200 서버] root
cat /app/state/reports/$(date +%F).txt     # 오늘 보고서. [알림] 줄이 할 일
b200                                        # 지금 현황
```

보고서에는 디스크 사용률, 사람별 작업 폴더 크기, 지난 하루 사람별 GPU 시간, 누군지 모르는 GPU 사용, 30일 넘게 안 쓴 이미지, GPU 오류(ECC, Xid)가 나와요. `[알림]` 줄은 팀원이 `b200` 을 입력할 때도 "관리자 알림"으로 보여요.

## 규칙 집행

규칙의 "안 지키면" 칸은 아래처럼 처리해요. 먼저 HIWARE 기록에서 누가 실행했는지 확인할 수 있어요.

| 상황 | 확인 | 처리 (root) |
|---|---|---|
| 누군지 모르는 GPU 사용(빨강) | `b200` 의 pid, 명령 | 팀 채널에 알리고, 1시간 안에 주인이 없으면 `kill <pid>` |
| 다른 그룹 GPU 빌려 쓰기(노랑), 주인 그룹이 요청 | `b200` | 30분 지나면 `b200 stop <세션>` 또는 `kill <pid>` |
| 디스크 80% 넘음 | 보고서, `b200 du` | 큰 순서로 정리 요청. 급하면 NAS로 옮김 |
| 오래된 이미지 | 보고서 | 30일 + 2주 지나면 `b200 rmi <이미지>` |

root 로 `b200 stop`, `b200 rmi` 를 쓰면 주인 확인 없이 처리돼요. root 로는 `b200 run`, `b200 docker` 가 막혀 있어요(작업은 공용 계정으로만).

## 도커 관리

```bash
# [B200 서버] root
systemctl status b200-docker            # 상태
systemctl restart b200-docker           # 다시 켜기(돌던 컨테이너는 멈춰요)
journalctl -u b200-docker -n 50         # 기록
b200 images                             # 이미지·들여온 사람·마지막 사용
runuser -u shareduser -- env DOCKER_HOST=unix:///run/user/$(id -u shareduser)/docker.sock /opt/b200/docker/current/docker system df
```

- 설정 파일: `/etc/b200/docker/daemon.json` (root 만 고쳐요). 저장 위치: `/app/docker`.
- 도커 판 올리기: 접근 PC에서 `docker_pack.ps1` 을 다시 실행해 새 묶음을 올리고 `docker_install.sh` 를 다시 실행해요. 예전 판은 `/opt/b200/docker/<판>` 에 남아 있어 되돌리기 쉬워요.

## 드라이버 업데이트

`admin_setup.sh` 가 NVIDIA 패키지를 고정(`apt-mark hold`)해 두었어요. 업데이트는 팀에 미리 알리고 GPU가 비었을 때 해요.

```bash
# [B200 서버] root
apt-mark unhold $(apt-mark showhold | grep -E 'nvidia|cuda|nvlsm')
# ... 서버 관리 팀과 드라이버·Fabric Manager 를 같은 판으로 업데이트 ...
bash /app/inbox/admin_setup.sh          # 다시 고정
b200 doctor                             # 확인
```

## 되돌리기

```bash
# [B200 서버] root
bash /app/inbox/admin_setup.sh --undo   # 접속 설정·정기 점검 지우기, 공용 폴더 잠금 풀기
systemctl disable --now b200-docker     # 도커 끄기
```
