# 서버 운영하기

설치를 마친 GPU 서버를 root 계정으로 관리할 때 자주 하는 일을 모았어요. 할 일마다 명령과 확인 방법이 있어요.
처음 설치는 `docs/1_처음_설치.md`, 각 기능이 왜 이렇게 생겼는지는 `docs/3_구조와_보안.md` 에 있어요.

- 도우미는 `admin_setup.sh` 가 `/app/admin/bin` 에 설치하는 `gpu`, `docker`, `nvidia-smi` 명령이에요. 공용 계정의 PATH 에만 있어서, root 로 접속했을 때는 전체 경로로 써요(예: `/app/admin/bin/gpu who`).
- 팀원에게 보여 줄 규칙과 엑셀은 `team/` 에 있어요. 서버에서 숫자나 배분을 바꾸면 `team/` 자료도 같이 고쳐요.

## 팀원 추가·삭제

| 할 일 | 서버 (root) | 엑셀 (`team/서버_사용_규칙.xlsx`) |
|---|---|---|
| 팀원 추가 | **두 서버 모두** `/app/admin/team.txt` 에 `이름 그룹` 한 줄 → `bash /app/inbox/admin_setup.sh`(작업 폴더와 NAS의 `backup/<이름>`, `docker_images/<이름>` 이 생겨요) | '팀원' 시트에 같은 내용 |
| 팀원 삭제 | 두 서버 모두 `team.txt` 에서 줄 삭제. 작업 폴더는 NAS로 옮긴 뒤 지워요(아래 명령) | '팀원' 시트에서 삭제 |

```bash
# [GPU 서버] root. 팀원 작업 폴더를 NAS로 옮기고 지우기(공용 계정 권한으로)
A=$(cat /etc/gpu/account); N=<이름>; T=/data/autonomy_sw
runuser -u "$A" -- rsync -a /app/autonomy_sw/$N/ $T/backup/$N/autonomy_sw/ && runuser -u "$A" -- rm -rf /app/autonomy_sw/$N
```

- 접속할 때 목록의 번호는 `team.txt` 에 적은 순서예요.
- 이름에는 `-`, `/`, 띄어쓰기를 쓸 수 없어요.
- 그룹 이름은 `gpu_alloc.txt` 의 그룹 이름과 글자까지 같아야 해요.
- `team.txt` 와 `gpu_alloc.txt` 는 서버마다 따로예요. 한 서버만 고치면 다른 서버에는 반영되지 않아요.
- 확인: 공용 계정으로 다시 접속하면 목록에 새 이름이 보이고, `/app/autonomy_sw/<이름>` 이 생겨 있어요.

## GPU 배분 바꾸기

`/app/admin/gpu_alloc.txt` 를 고치고, 엑셀 'GPU 배분' 시트도 같게 고쳐요. 형식은 한 줄에 `GPU번호  그룹` 이에요.

| 그룹 이름 | 뜻 |
|---|---|
| 팀 그룹(예: `인지`, `판단`) | 그 그룹의 GPU. 다른 그룹이 고르면 "빌려 쓰는 것" 이라고 경고만 해요 |
| `공용` | 누구나 선착순 |
| `다른팀` | 다른 팀 GPU(서버 2의 0~3번). 우리 팀은 쓰지 않아요 |

- `gpu_alloc.txt` 는 서버마다 따로예요. 처음 만들 때 `admin_setup.sh` 가 서버 번호(1 또는 2)를 물어보고, 답에 맞는 배분으로 만들어요. 잘못 골랐으면 파일을 지우고 `admin_setup.sh` 를 다시 실행해요.
- 팀 사이의 배분(서버 2의 0~3번은 다른 팀)은 확정이에요. 우리 팀 안의 그룹 배분(서버 1의 인지·판단·공용, 서버 2의 4 인지, 5 판단, 6·7 공용)은 두 서버 모두 임시예요.
- `다른팀` GPU는 "GPU별 사용자" 표에 "다른 팀" 으로 보이고, 빈 GPU 목록에서 빠져요. 거기서 도는 다른 팀 프로세스에는 알림을 보내지 않아요.
  우리 팀원이 그 GPU를 고르면 `docker run` 전에 경고하고 한 번 물어봐요. 그래도 쓰면 그 사람과 관리자에게 하루 한 번 알려요.
- 확인: `/app/admin/bin/gpu who` 의 배분 칸이 바뀌어요.

## 알림 확인하고 기준 바꾸기

정기 점검이 10분마다 GPU와 디스크를 확인하고, 아래 경우에만 알려요. 멈추거나 지우지는 않아요.

| 알림 | 받는 사람 | 기준(`/app/admin/gpu.conf`) | 얼마나 자주 |
|---|---|---|---|
| 한 GPU를 두 사람 이상이 씀 | 그 사람들 | | 하루 한 번 |
| GPU를 잡고 사용률 0% | 그 사람 | `IDLE_HOURS=12` | 하루 한 번 |
| 다른 팀 GPU를 씀(서버 2) | 그 사람, 관리자 | | 하루 한 번 |
| 디스크 사용량이 기준을 넘음 | 작업 폴더가 큰 3명, 관리자 | `DISK_ALERT=85` | 주 한 번 |
| 오래 안 쓴 도커 이미지 | 들여온 사람(모르면 관리자) | `IMAGE_NOTICE_DAYS=30` | 주 한 번 |
| 이름 없는 GPU 작업 | 관리자 | | 하루 한 번 |
| GPU 오류(ECC, Xid) | 관리자 | | 하루 한 번 |
| 주간 보고서(월요일 07:40) | 관리자 | `NAS_DIR`(NAS 팀 폴더, 기본 `/data/autonomy_sw`. 폴더별 사용량도 보여 줘요) | 주 한 번 |

- 팀원은 열어 둔 터미널 창에 한 줄로 알림을 받고, 다음에 접속할 때도 볼 수 있어요. 관리자는 root 로 접속할 때 봐요.
- 알림 기록: `/app/state/notice/<이름>.txt`. 주간 보고서: `/app/state/reports/<날짜>.txt`.
- `docker run` 할 때의 경고 기준인 `MAX_GPUS=4`(한 사람이 쓰는 GPU 장수)도 같은 파일에 있어요.
- 숫자를 바꾸면 `team/` 문서와 엑셀의 숫자도 같이 바꿔요.

## 도커 관리

```bash
# [GPU 서버] root
systemctl status gpu-docker            # 상태
systemctl restart gpu-docker           # 다시 켜기(돌던 컨테이너는 멈춰요)
journalctl -u gpu-docker -n 50         # 기록
/app/admin/bin/gpu who                # GPU별 쓰는 사람
/app/admin/bin/gpu docker ps -a              # 공용 계정 도커를 root 에서 볼 때(공용 계정 설정은 읽지 않아요)
```

- 설정 파일: `/etc/gpu/docker/daemon.json` (root 만 고쳐요). 저장 위치: `/app/docker`.
- 기본 런타임은 runc 예요. nvidia 를 기본으로 하면 `--gpus` 없이 띄운 CUDA 이미지에도 GPU 8장이 모두 보이기 때문에 바꾸지 않아요.
- 오래된 이미지는 알림만 가요. 지워야 하면 들여온 사람에게 먼저 말하고 `/app/admin/bin/gpu docker rmi <이미지>` 로 지워요.
- 도커 버전 올리기: 접근 PC에서 `docker_pack.ps1` 을 다시 실행해 새 묶음을 올리고 `docker_install.sh` 를 다시 실행해요. **돌고 있는 컨테이너는 모두 멈춰요.** 그래서 스크립트가 개수를 보여 주고 한 번 물어봐요. 팀에 미리 알리고 GPU가 빌 때 하세요. 예전 버전은 `/opt/gpu/docker/<판>` 에 남아 있어 되돌리기 쉬워요.

## 서버 화면 프로그램

서버 화면(컨테이너 밖)에서 쓰는 tmux, nvtop, rsync 같은 프로그램은 OS 패키지예요. 서버에 인터넷이 없어서 관리자가 묶음으로 설치해요(`docs/1_처음_설치.md` 의 "1-1단계: 서버 기초 프로그램"). 빠진 것은 `check.sh` 가 패키지 이름으로 알려 줘요. 목록에 프로그램을 더하려면 그 절 끝의 안내대로 세 곳을 같이 고치고 묶음을 새로 만들어 `pkgs_install.sh` 를 다시 실행해요(없는 것만 설치해요). Python 패키지는 공용으로 두지 않아요(팀원이 이미지에 넣어 와요).

## 설치 스크립트만 고쳐서 다시 올리기

`server/` 의 스크립트를 고쳤다면 `setup_pack.ps1` 로 묶음을 새로 만들어 `gpu fetch gpu-setup.tar` 로 들여와도 되고, 그 파일 하나만 다시 들여와도 돼요.

1. 공용 계정의 FileZilla로 그 파일 하나를 `/app/upload` 에 올려요(폴더 없이 파일만).
2. root 로 복사하고 지문을 봐요. 접근 PC의 `Get-FileHash server\<파일>` 값과 같으면 실행해요.

```bash
# [GPU 서버] root. 예: admin_setup.sh 를 고쳤을 때
cp /app/upload/admin_setup.sh /app/inbox/admin_setup.sh && sha256sum /app/inbox/admin_setup.sh
# 예: 도우미 gpu 를 고쳤을 때(bin 아래로 복사한 뒤 admin_setup.sh 를 다시 실행해야 /app/admin/bin 에 설치돼요)
cp /app/upload/gpu /app/inbox/bin/gpu && sha256sum /app/inbox/bin/gpu      # 지문 확인
bash /app/inbox/admin_setup.sh                                                  # 같을 때만
```

## 드라이버 업데이트

`admin_setup.sh` 는 드라이버 버전을 고정하지 않아요. 드라이버 업데이트는 서버 관리 팀이 정해요. 업데이트한다는 말을 들으면 팀에 미리 알리고, 끝난 뒤 GPU 계산까지 되는지 확인해요.

```bash
# [GPU 서버] root. 드라이버 업데이트 뒤
/app/admin/bin/gpu doctor <PyTorch 이미지>   # GPU 계산까지 확인(이미지를 붙여야 계산을 봐요)
```

## 되돌리기

```bash
# [GPU 서버] root
bash /app/inbox/admin_setup.sh --undo   # 접속 설정·정기 점검 지우기(/app/admin·/app/inbox 잠금은 그대로)
systemctl disable --now gpu-docker     # 도커 끄기
```

`--undo` 를 해도 `gpu` 명령, `/app/admin`·`/app/inbox` 잠금, 기록(`/app/state`)은 그대로 남아요. 다시 쓰려면 `bash /app/inbox/admin_setup.sh` 를 실행해요.
