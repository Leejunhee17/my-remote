# 서버 운영하기

설치를 마친 B200 서버를 root 계정으로 관리할 때 자주 하는 일을 모았어요. 할 일마다 명령과 확인 방법이 있어요.
처음 설치는 `docs/1_처음_설치.md`, 각 장치가 왜 이렇게 생겼는지는 `docs/3_구조와_보안.md` 에 있어요.

- root 화면에서 도우미 명령은 전체 경로로 써요(예: `/app/shared/bin/b200 who`). 도우미는 공용 계정의 PATH 에만 있어요.
- 팀원에게 보여 줄 규칙과 엑셀은 `team/` 에 있어요. 서버에서 숫자나 배분을 바꾸면 `team/` 자료도 같이 고쳐요.

## 팀원 추가·삭제

| 할 일 | 서버 (root) | 엑셀 (`team/서버_사용_규칙.xlsx`) |
|---|---|---|
| 팀원 추가 | **두 서버 모두** `/app/shared/team.txt` 에 `이름 그룹` 한 줄 → `bash /app/inbox/admin_setup.sh`(작업 폴더, NAS를 정했으면 NAS 폴더도 생성) | '팀원' 시트에 같은 내용 |
| 팀원 삭제 | 두 서버 모두 `team.txt` 에서 줄 삭제. 작업 폴더는 NAS로 옮긴 뒤 지워요(아래 명령) | '팀원' 시트에서 삭제 |

```bash
# [B200 서버] root. 팀원 작업 폴더를 NAS로 옮기고 지우기(공용 계정 권한으로)
A=$(cat /etc/b200/account); N=<이름>; T=/data/<팀 폴더>
runuser -u "$A" -- rsync -a /app/workspace/$N/ $T/backup/$N/workspace/ && runuser -u "$A" -- rm -rf /app/workspace/$N
```

- 접속할 때 목록의 번호는 `team.txt` 에 적은 순서예요.
- 이름에는 `-`, `/`, 띄어쓰기를 쓸 수 없어요.
- 그룹 이름은 `gpu_alloc.txt` 의 그룹 이름과 글자까지 같아야 해요.
- `team.txt` 와 `gpu_alloc.txt` 는 서버마다 따로예요. 한 서버만 고치면 다른 서버 목록에는 없어요.
- 확인: 공용 계정으로 다시 접속하면 목록에 새 이름이 보이고, `/app/workspace/<이름>` 이 생겨 있어요.

## GPU 배분 바꾸기

`/app/shared/gpu_alloc.txt` 를 고치고, 엑셀 'GPU 배분' 시트도 같게 고쳐요. 형식은 한 줄에 `GPU번호  그룹` 이에요.

| 그룹 이름 | 뜻 |
|---|---|
| 팀 그룹(예: `인지`, `판단`) | 그 그룹 GPU. 다른 그룹이 고르면 "빌려 쓰는 것" 이라고 경고만 해요 |
| `공용` | 누구나 선착순 |
| `다른팀` | 다른 팀 GPU(서버 2의 0~3번). 우리 팀은 쓰지 않아요 |

- `gpu_alloc.txt` 는 서버마다 따로예요. 처음 만들 때 서버 이름이 `p2` 로 끝나면 서버 2 배분으로 만들어요.
- 서버 2의 지금 배분(4 인지, 5 판단, 6·7 공용)은 임시예요.
- `다른팀` GPU는 "누가 쓰나" 표에 "다른 팀" 으로 보이고, 빈 GPU 목록에서 빠져요. 거기서 도는 다른 팀 프로세스에는 알림을 보내지 않아요.
  우리 팀이 그 GPU를 고르면 `docker run` 전에 경고하고 한 번 물어봐요. 그래도 쓰면 그 사람과 관리자에게 하루 한 번 알려요.
- 확인: `/app/shared/bin/b200 who` 의 배분 칸이 바뀌어요.

## 알림 확인하고 기준 바꾸기

10분마다 GPU와 디스크를 보고, 아래 경우에만 알려요. 멈추거나 지우지는 않아요.

| 알림 | 받는 사람 | 기준(`/app/shared/b200.conf`) | 얼마나 자주 |
|---|---|---|---|
| 한 GPU를 두 사람 이상이 씀 | 그 사람들 | | 하루 한 번 |
| GPU를 잡고 사용률 0% | 그 사람 | `IDLE_HOURS=12` | 하루 한 번 |
| 다른 팀 GPU를 씀(서버 2) | 그 사람, 관리자 | | 하루 한 번 |
| 디스크가 참 | 작업 폴더가 큰 3명, 관리자 | `DISK_ALERT=85` | 주 한 번 |
| 오래 안 쓴 도커 이미지 | 들여온 사람(모르면 관리자) | `IMAGE_NOTICE_DAYS=30` | 주 한 번 |
| 이름 없는 GPU 작업 | 관리자 | | 하루 한 번 |
| GPU 오류(ECC, Xid) | 관리자 | | 하루 한 번 |
| 주간 보고서(월요일 07:40) | 관리자 | `NAS_DIR`(적으면 NAS 팀 폴더 사용량도) | 주 한 번 |

- 팀원은 열어 둔 창에 한 줄로 받고, 다음에 접속할 때도 봐요. 관리자는 root 로 접속할 때 봐요.
- 알림 기록: `/app/state/notice/<이름>.txt`. 주간 보고서: `/app/state/reports/<날짜>.txt`.
- `docker run` 때의 경고 기준 `MAX_GPUS=4`(한 사람 GPU 장수)도 같은 파일에 있어요.
- 숫자를 바꾸면 `team/` 문서와 엑셀의 숫자도 같이 바꿔요.

## 도커 관리

```bash
# [B200 서버] root
systemctl status b200-docker            # 상태
systemctl restart b200-docker           # 다시 켜기(돌던 컨테이너는 멈춰요)
journalctl -u b200-docker -n 50         # 기록
/app/shared/bin/b200 who                # GPU별 쓰는 사람
/app/shared/bin/b200 docker ps -a              # 공용 계정 도커를 root 에서 볼 때(공용 계정 설정은 읽지 않아요)
```

- 설정 파일: `/etc/b200/docker/daemon.json` (root 만 고쳐요). 저장 위치: `/app/docker`.
- 기본 런타임은 runc 예요. nvidia 를 기본으로 하면 `--gpus` 없이 띄운 CUDA 이미지에도 GPU 8장이 모두 보여서 바꾸지 않아요.
- 오래된 이미지는 알림만 가요. 지워야 하면 들여온 사람에게 먼저 말하고 `/app/shared/bin/b200 docker rmi <이미지>` 로 지워요.
- 도커 판 올리기: 접근 PC에서 `docker_pack.ps1` 을 다시 실행해 새 묶음을 올리고 `docker_install.sh` 를 다시 실행해요. **돌고 있는 컨테이너가 있으면 모두 멈춰서** 스크립트가 개수를 보여 주고 한 번 물어봐요. 팀에 미리 알리고 GPU가 빌 때 하세요. 예전 판은 `/opt/b200/docker/<판>` 에 남아 있어 되돌리기 쉬워요.

## 기초 프로그램 바꾸기

목록을 바꾸거나 기초 프로그램을 다시 까는 방법은 `docs/5_기초프로그램.md` 에 있어요. Python 패키지는 공용으로 두지 않아요(팀원이 이미지에 넣어 와요).

## 설치 스크립트만 고쳐서 다시 올리기

`server/` 의 스크립트를 고쳤다면 그 파일 하나만 다시 들여와도 돼요. 설치 스크립트는 체크섬 검사에서 빠져 있어서 "깨졌어요" 오류가 나지 않아요.

1. 공용 계정의 FileZilla로 그 파일 하나를 `/app/upload` 에 올려요(폴더 없이 파일만).
2. root 로 복사하고 지문을 봐요. 접근 PC의 `Get-FileHash server\<파일>` 값과 같으면 실행해요.

```bash
# [B200 서버] root. 예: admin_setup.sh 를 고쳤을 때
cp /app/upload/admin_setup.sh /app/inbox/admin_setup.sh && sha256sum /app/inbox/admin_setup.sh
# 예: 도우미 b200 을 고쳤을 때(bin 아래로 복사한 뒤 admin_setup.sh 를 다시 실행해야 /app/shared/bin 에 깔려요)
cp /app/upload/b200 /app/inbox/bin/b200 && sha256sum /app/inbox/bin/b200      # 지문 확인
bash /app/inbox/admin_setup.sh                                                  # 같을 때만
```

## 드라이버 업데이트

- 서버 1은 `admin_setup.sh` 가 NVIDIA 패키지를 고정(`apt-mark hold`)해 두었어요. 업데이트는 팀에 미리 알리고 GPU가 비었을 때 해요.
- 서버 2는 다른 팀과 같이 써서 고정하지 않아요. 드라이버 업데이트는 서버 관리 팀·다른 팀과 정해요.

```bash
# [B200 서버 1] root
apt-mark showhold                      # 고정된 패키지 확인
apt-mark unhold $(apt-mark showhold)   # 모두 풀기(admin_setup.sh 가 고정한 것: nvidia·libnvidia·cuda-drivers·nvlsm·libnvsdm·datacenter-gpu-manager)
# ... 서버 관리 팀과 드라이버·Fabric Manager 를 같은 판으로 업데이트 ...
bash /app/inbox/admin_setup.sh          # 다시 고정
/app/shared/bin/b200 doctor <PyTorch 이미지>   # GPU 계산까지 확인(이미지를 붙여야 계산을 봐요)
```

## 되돌리기

```bash
# [B200 서버] root
bash /app/inbox/admin_setup.sh --undo   # 접속 설정·정기 점검 지우기(공용 폴더 잠금은 그대로)
systemctl disable --now b200-docker     # 도커 끄기
```

`--undo` 는 `b200` 명령, 공용 폴더 잠금, 기록(`/app/state`), 드라이버 고정은 그대로 둬요. 다시 쓰려면 `bash /app/inbox/admin_setup.sh` 를 실행해요.
