# 세그멘테이션 데이터셋 받기와 구조

학습에 쓰는 시맨틱 세그멘테이션 데이터셋 7개를 접근 PC에서 받아 GPU 서버의 `/app/shared/datasets` 에 푸는 방법과, 풀린 뒤 학습 코드가 읽는 폴더 구조예요.
처음 설치는 `docs/1_처음_설치.md` 의 4단계(접근 PC `pc\datasets_download.ps1` → GPU 서버 `server/datasets_install.sh`)를 따르세요.

## 데이터셋 목록

7개 모두 2D 이미지와 라벨만 받아요. 합계는 약 112 GB예요.

| 데이터셋 | 폴더 | 크기 | 받는 곳 | 받는 방법 |
|---|---|---|---|---|
| GOOSE | `goose` | 27 GB | goose-dataset.de | 스크립트가 직접 링크로 받아요 |
| GOOSE-Ex | `gooseEx` | 19 GB | goose-dataset.de | 스크립트가 직접 링크로 받아요 |
| RUGD | `RUGD` | 5.4 GB | rugd.vision | 스크립트가 직접 링크로 받아요 |
| WildScenes | `wildscenes` | 47 GB | [CSIRO 데이터 포털](https://data.csiro.au/collection/csiro:61541) | 스크립트가 AWS CLI로 받아요. 접속 정보가 필요해요 |
| RELLIS-3D | `rellis_2d` | 11 GB | Google Drive | Drive에 접속되면 스크립트가 curl로 받아요 |
| TAS500 v1.1 | `tas500v1.1` | 1.1 GB | Google Drive | Drive에 접속되면 스크립트가 curl로 받아요 |
| GO(The Great Outdoors) | `go` | 1.6 GB | Google Drive | Drive에 접속되면 스크립트가 curl로 받아요 |

- GO의 라이선스는 CC BY-NC-SA 3.0이라 비상업 용도로만 쓸 수 있어요.
- 지금 접근 PC에서는 Google Drive 접근이 막혀 있어요. 막혀 있는 동안 스크립트는 Drive 데이터셋 3개를 건너뛰고, 접근이 풀린 뒤 다시 실행하면 그때 받아요. 워크스테이션의 `~/datasets/semantic_segmentation/` 에 있는 사본을 써도 돼요.

## 받고 설치하기

```powershell
# [접근 PC] PowerShell
cd D:\b200
powershell -ExecutionPolicy Bypass -File .\pc\datasets_download.ps1
```

`D:\b200\datasets` 폴더를 통째로 공용 계정의 FileZilla로 GPU 서버의 `/app/upload` 에 올리세요. root 로 새로 복사해 지문을 확인한 뒤 설치하세요(지문은 접근 PC 스크립트 끝에 나와요).

```bash
# [GPU 서버] root
/app/shared/bin/b200 fetch datasets                  # 새로 복사하고 지문을 보여 줘요. 접근 PC 화면의 지문과 같은지
bash /app/inbox/datasets/datasets_install.sh
```

- `-Only goose,RUGD` 처럼 폴더 이름을 쉼표로 이어 붙이면 일부만 받을 수 있어요. 다 받은 것만 먼저 올려도 돼요.
- 끝나면 데이터셋마다 라벨이 몇 장 있는지 보여 줘요. "라벨을 못 찾음" 이 나오면 아래 "학습 코드가 읽는 라벨 위치" 를 보세요.
- WildScenes 와 Google Drive 데이터셋은 아래 절에 나온 준비가 더 필요해요.

## WildScenes 접속 정보 받기

WildScenes는 CSIRO 데이터 포털의 S3 저장소에서 받아요. 접속 정보는 요청할 때마다 새로 발급되고 **약 48시간만 유효**해서, 내려받기를 시작하기 직전에 받으세요.
따로 설치할 프로그램은 없어요. 스크립트가 uv로 AWS CLI를 실행해요.

1. [CSIRO 데이터 포털의 WildScenes 페이지](https://data.csiro.au/collection/csiro:61541)에서 **Download** → **Download files via S3 Client** 를 선택하세요. 스크립트도 실행 중에 이 페이지를 브라우저로 열지 물어봐요.
2. 화면의 Download Information에서 아래 네 값을 확인하세요. 값 옆의 복사 아이콘으로 복사할 수 있어요.

   | 항목 | 예시 |
   |---|---|
   | Server | `s3.data.csiro.au` |
   | Remote Directory | `dapprd/000012345v001/` |
   | Access Key | 영문·숫자 20자 정도 |
   | Secret Access Key | 영문·숫자·기호 40자 정도 |

3. `pc\datasets_download.ps1` 을 `-WildScenes` 를 붙여 실행하세요. 스크립트가 네 값을 차례로 물어보면 붙여 넣으세요. 두 키는 화면과 기록 파일에 남지 않아요.
   네 값을 `.env` 의 `WILDSCENES_S3_SERVER`, `WILDSCENES_S3_DIR`, `WILDSCENES_ACCESS_KEY`, `WILDSCENES_SECRET_KEY` 에 적어 두면 `-WildScenes` 없이도 묻지 않고 WildScenes 까지 받아요(`docs/1_처음_설치.md` 의 "접근 PC 설정(.env)").
4. 48시간 안에 다 못 받았으면 포털에서 접속 정보를 새로 받아 같은 명령을 다시 실행하세요. 이미 받은 파일은 건너뛰어요.

### WildScenes 링크 목록으로 받기 (AWS CLI 방식이 안 될 때)

회사 프록시가 윈도우 로그인 인증을 요구하는 망에서는 AWS CLI가 `s3.data.csiro.au` 에 접속하지 못해요. 브라우저에서 `https://s3.data.csiro.au/` 가 401이나 AccessDenied라도 뜨는데 스크립트만 `curl 오류 56` 으로 실패하면 이 경우예요.
이때는 포털이 주는 파일 링크 목록을 curl로 받으세요. curl은 브라우저처럼 윈도우 로그인으로 프록시 인증을 할 수 있어요.

1. [WildScenes 페이지](https://data.csiro.au/collection/csiro:61541)에서 **Download** → **Get a list of file download links** → **Request files** 를 누르고, 약관에 동의한 뒤 **Download file links** 를 누르세요. `.txt` 파일 하나를 내려받게 돼요.
2. 그 파일 경로를 붙여 아래처럼 실행하세요. 접속 정보는 묻지 않아요. 경로를 `.env` 의 `WILDSCENES_LINKS` 에 적어 두면 붙이지 않아도 돼요.

   ```powershell
   # [접근 PC] PowerShell
   cd D:\b200
   powershell -ExecutionPolicy Bypass -File .\pc\datasets_download.ps1 -WildScenesLinks "$env:USERPROFILE\Downloads\받은파일.txt"
   ```

- 목록에는 3D 데이터까지 모든 파일이 들어 있지만, 스크립트는 `WildScenes2d` 아래 파일만 받아요.
- 스크립트는 다 받은 파일을 `datasets\wildscenes.links_done.txt` 에 적어 두고, 다시 실행하면 남은 것만 받아요.
- 링크에는 유효 기간이 있어요. `링크가 만료됐어요(403)` 가 나오면 1번을 다시 해서 새 목록으로 같은 명령을 실행하세요.

## Google Drive 데이터셋 받기

RELLIS-3D, TAS500, GO는 Google Drive에만 있어요. 스크립트는 gdown 같은 별도 도구 없이 curl로 받아요. Drive가 실제 파일을 내려 주는 주소(`drive.usercontent.google.com`)가 이어받기를 지원해서, 직접 링크 데이터셋과 똑같이 끊기면 이어받고 다 받으면 압축 손상을 검사해요. 큰 파일에서 Drive가 보여 주는 "바이러스 검사를 할 수 없음" 확인 페이지도 스크립트가 넘겨요.

- Drive에 접속되지 않으면 이 3개는 건너뛰고 나머지를 받아요. 접근이 풀린 뒤 같은 명령을 다시 실행하세요.
- 점검 단계에서는 Drive 첫 페이지뿐 아니라 실제 파일 하나의 앞부분까지 받아 봐요. 첫 페이지는 열리는데 파일 받기만 막힌 망을 미리 찾아내기 위해서예요.
- 받다가 403 같은 거절이 나오면 몇 시간씩 다시 시도하지 않고, 바로 이유를 가려 알려 줘요.

| 화면에 나오는 이유 | 뜻 | 할 일 |
|---|---|---|
| 회사 프록시나 보안 장비가 막았어요 | Google이 아니라 회사 장비가 거절했어요. 응답 머리글에 Google 표시가 없는 것으로 알 수 있어요 | 사내 IT에 `drive.usercontent.google.com` 파일 다운로드 허용을 요청하세요. 화면의 Server와 페이지 제목을 같이 알려 주세요 |
| Google 다운로드 한도 초과 | 최근 이 파일을 받은 사람이 많아 Google이 하루쯤 막았어요. 공개 데이터셋에서 자주 생겨요 | 다음 날 다시 실행하세요. 급하면 브라우저에서 로그인해 "내 드라이브에 사본 만들기"를 한 뒤 사본을 받아 넣으세요 |
| 로그인이나 접근 권한이 필요해요 | 공유 설정이 바뀌었어요 | 브라우저에서 로그인해 받아 넣으세요 |
| Google이 이 망의 요청을 자동 요청으로 보고 막았어요 | 회사 전체가 같은 IP로 나가는 망에서 생겨요 | 몇 시간 뒤 다시 하거나 브라우저로 받아 넣으세요 |

파일마다 받을 수 있는지만 확인하려면 진단 모드로 실행하세요. 아무것도 받지 않고, 응답 내용을 `datasets\drive_check` 폴더에 남겨요.

## 스크립트가 하는 일

### 접근 PC: pc\datasets_download.ps1

1. **점검**: uv, curl, tar가 있는지, 사이트마다 인터넷 접속이 되는지, WildScenes 접속 정보가 맞는지, 남은 공간이 충분한지 확인해요. Google Drive에 접속되는지도 확인해서 알려 줘요. Drive가 막혀 있어도 멈추지 않고 나머지를 받아요.
2. **내려받기**: 인터넷이 끊기면 기다렸다가 이어서 받아요. 받은 양이 늘고 있는 동안은 몇 번 끊겨도 계속 이어받아요. 받은 양이 전혀 늘지 않은 채 연속 30번 끊길 때만(기다리는 시간이 30초씩 늘어 최대 5분, 합쳐서 약 2시간) 그 파일을 포기하고 다음 파일로 넘어가요.
   - 직접 링크(GOOSE, GOOSE-Ex, RUGD): `curl -C -` 로 이어받아요.
   - WildScenes: `aws s3 sync` 가 이미 받은 파일을 건너뛰어요. 끝나면 빠진 파일이 없는지 한 번 더 확인해요.
   - Google Drive 데이터셋: Drive에 접속되면 curl로 이어받아요. 직접 넣어 둔 압축 파일이 있으면 그것도 검사해요.
3. **검사**: 압축 파일을 끝까지 읽어 손상 여부를 확인해요. 받은 파일이 손상됐으면 지우고 처음부터 다시 받아요.
4. **올릴 준비**: GPU 서버에서 확인할 체크섬 목록(`MANIFEST.sha256`)과 GPU 서버 스크립트를 `datasets` 폴더에 넣어요.
5. **결과**: 데이터셋별 결과와 GPU 서버에 올릴 것을 보여 줘요.

검사까지 끝난 파일 옆에는 `.ok` 파일이 생겨요. 다시 실행하면 `.ok` 가 있는 파일은 건너뛰어요. 처음부터 다시 받으려면 그 파일과 `.ok` 파일을 지우고 다시 실행하세요.
`-Only goose,RUGD` 처럼 폴더 이름을 쉼표로 이어 붙이면 일부만 받을 수 있어요. 다 받은 것만 먼저 GPU 서버에 올려도 돼요.

### GPU 서버: server/datasets_install.sh

1. **점검**: 체크섬으로 올리는 중에 손상되거나 빠진 파일이 있는지, WildScenes 파일 수가 맞는지, 남은 공간이 충분한지 확인해요.
2. **풀기**: `/app/shared/datasets/<폴더>` 아래에 풀어요. 이미 푼 파일은 건너뛰어요.
3. **검사**: 아래 "학습 코드가 읽는 라벨 위치" 에 라벨이 몇 장 있는지 세고, RUGD 색상표 파일이 있는지 확인해요.

## 학습 코드가 읽는 라벨 위치

`semantic_segmentation_train` 저장소의 `data/catalog.py` 가 읽는 위치예요. GPU 서버 스크립트도 이 위치에서 라벨을 세어 보여 줘요.
"라벨을 못 찾음" 이 나오면 압축 안의 폴더가 한 단계 더 있거나 없는 경우가 대부분이에요. 화면의 "지금 구조" 를 보고 아래 위치에 맞게 폴더를 옮기세요.

| 데이터셋 | 라벨 위치 (`/app/shared/datasets/` 아래) |
|---|---|
| GOOSE | `goose/goose_2d_*/labels/**/*_labelids.png` |
| GOOSE-Ex | `gooseEx/gooseEx_2d_*/labels/**/*_labelids.png` |
| RELLIS-3D | `rellis_2d/annotations_id/Rellis-3D/*/*/*.png` |
| RUGD | `RUGD/RUGD_annotations/*/*.png` |
| WildScenes | `wildscenes/*/indexLabel/*.png` |

| GO | `go/*/pylon_camera_node_label_id/*.png` (원본 구조 기준이에요. 워크스테이션 사본과 비교하세요) |

RUGD의 색상표 파일 `RUGD/RUGD_annotation-colormap.txt` 는 따로 받는 링크가 없어요. 압축 안에 있으면 GPU 서버 스크립트가 제자리로 복사하고, 없으면 워크스테이션의 `~/datasets/semantic_segmentation/RUGD/` 에서 복사하세요.
