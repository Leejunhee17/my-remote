# 서버 구조와 보안

팀원 여럿이 공용 계정 하나(`shareduser`)로 B200 서버를 같이 쓰는 구조가 어떻게 생겼고, 왜 그렇게 정했는지 설명해요.
설정을 바꾸거나 이상한 동작을 이해해야 할 때 읽어요. 할 일 위주의 방법은 `docs/2_서버_운영.md` 에 있어요.

## 정한 방향

- **팀원에게 새 명령을 외우게 하지 않아요.** 팀원은 `docker`, `nvidia-smi`, FileZilla를 평소처럼 쓰고, 도우미가 그 뒤에서 이름표를 붙이고 경고해요.
- **막기보다 알려요.** 멈추거나 지우는 것은 관리자가 판단해요. 알림도 같은 내용은 하루나 한 주에 한 번만 보내요.
- **공용 계정으로는 root 가 될 수 없게 해요.** 계정을 같이 쓰니 누가 무엇을 했는지 가리기 어려워요. 그래서 root 권한으로 가는 길만은 막아요.

## 구조 한눈에

| 누가 | 계정 | 할 수 있는 것 |
|---|---|---|
| 팀원 | `shareduser`(HIWARE 경유, 공용) | `/app/workspace` 쓰기, rootless 도커 |
| 관리자 | root(HIWARE 경유, 나만) | 전부. 공용 폴더·설치 파일·시스템 설정·도커 서비스 |

| 장치 | 하는 일 | 만드는 곳 |
|---|---|---|
| 잠금 | `/app/shared`(기초 프로그램·데이터셋·모델)와 `/app/inbox`(관리자 설치 파일)는 root 만 고쳐요 | `admin_setup.sh` |
| 접속 설정(`/etc/profile.d/b200.sh`) | 접속하면 GPU 현황을 보여 주고 이름을 번호로 고르게 해요. 이름별 작업 폴더·캐시·명령 기록·tmux, 안 본 알림 보여 주기. 안 골라도 접속은 돼요 | `admin_setup.sh` |
| `docker` 도우미 | `run`·`create`에 이름표(`b200.USER`, `b200.GPUS`)를 붙여요. 남이 쓰는 GPU·다른 팀 GPU·`--gpus all`이면 경고하고 한 번 물어봐요. 다른 그룹 GPU, 1인 4장 초과는 경고만. `load`·`build`·`commit` 때 이미지를 들여온 사람을 적어요 | `server/bin/docker` |
| `nvidia-smi` 도우미 | 옵션 없이 실행하면 원래 표 아래에 "누가 쓰나"(GPU별 이름·그룹·컨테이너)를 붙여요. 옵션이 있으면 원래 그대로 | `server/bin/nvidia-smi` |
| `docker ps` | USER, GPUS 열을 보여 줘요(공용 계정의 `~/.docker/config.json`) | `admin_setup.sh` |
| rootless 도커(`b200-docker` 서비스) | 컨테이너로 root 권한을 얻는 길을 막아요. `--gpus` 로 정한 GPU만 컨테이너에 보여요 | `docker_install.sh` |
| 정기 점검(10분) | GPU 사용 기록과 알림 | `admin_setup.sh`(cron), `server/bin/b200` |
| 주간 보고서(월요일 07:40) | 사람별 GPU 시간, 디스크, 이미지, 지난주 알림 | `admin_setup.sh`(cron) |

## 사람을 구분하는 방법

공용 계정이라 서버 입장에서는 모두 같은 사람이에요. 그래서 접속할 때 고른 이름(`B200_USER`)으로 구분해요.

| GPU 프로세스가 | 누구로 보나 |
|---|---|
| 컨테이너 안에 있음 | 그 컨테이너의 이름표(`b200.USER`). 이름표가 없으면 컨테이너 이름만 보여요 |
| 서버에서 직접 실행 | 프로세스 환경의 `B200_USER`(접속할 때 고른 이름이 따라가요) |
| 둘 다 아님 | 작업 폴더(`/app/workspace/<이름>`) 안에서 실행했으면 그 이름, 아니면 "이름 없음" |

이름은 본인이 고르는 것이라 남의 이름을 고를 수도 있어요. 팀 안의 약속으로 충분하다고 보고, 따로 막지 않아요.

### GPU 사용 기록을 남기는 이유

공용 계정이라 `nvidia-smi` 만으로는 누가 GPU를 쓰는지 알 수 없어요. 10분마다 "GPU, 이름, 컨테이너, 사용률"을 `/app/state/gpu_log/<월>.tsv` 에 적어 두면 세 가지를 할 수 있어요.

- GPU를 잡고 놀고 있는지 알 수 있어요. 한 번 볼 때 0%인 것은 흔하니까, 12시간 내내 0%인지는 기록이 있어야 판단할 수 있어요.
- 그룹별 배분이 실제 사용량과 맞는지 주간 보고서로 볼 수 있어요. 배분을 바꿀 근거가 돼요.
- 다툼이 생기면 언제 누가 썼는지 확인할 수 있어요.

## 다른 팀과 같이 쓰는 서버(서버 2)

서버 2는 다른 팀과 같이 쓰고, 우리 팀은 GPU 4~7번만 써요. 남의 서버에 우리 규칙을 거는 것은 부담이라, 우리 설정은 **우리 공용 계정(`shareduser`)에만** 걸리고 다른 팀 계정과 서버 전체 설정은 건드리지 않아요.
`gpu_alloc.txt` 에 `다른팀` 줄이 있으면 같이 쓰는 서버로 봐요.

| 무엇 | 우리 공용 계정 | 다른 계정(다른 팀, root) |
|---|---|---|
| `docker`, `nvidia-smi` 도우미, 이름 고르기, 알림 | 걸려요 | 그대로(평소 명령) |
| 우리 도커(rootless) | 우리 계정만 써요 | 다른 팀 도커와 따로예요 |
| GPU 연결 설정(`no-cgroups`) | 우리 도커 전용 파일 `/etc/b200/docker/nvidia-container-runtime` | 서버 전체 설정 그대로 |
| buildx·compose | `/opt/b200/docker/cli-plugins` | 그대로 |
| NVIDIA Container Toolkit | 이미 깔려 있으면 판이 달라도 그대로 써요 | 그대로 |
| 드라이버 고정(`apt-mark hold`) | 하지 않아요 | 그대로 |
| 정기 점검 | 우리 GPU(4~7번)와 우리 계정 프로세스만 봐요 | 다른 팀 프로세스는 들여다보지 않아요 |
| `/app` 잠금 | 우리 폴더만 써요 | 다른 계정 폴더가 있으면 잠그기 전에 물어봐요 |

- GPU 사용도 다른 팀에는 아무것도 하지 않아요. 우리 팀원이 다른 팀 GPU(0~3번)를 고를 때만 경고해요.
- 서버 전체에 남는 것은 네 가지예요.
  - GPU 서비스 켜기(Fabric Manager, persistenced): 원래 켜져 있어야 하는 서비스예요.
  - rootless 도커에 필요한 시스템 패키지: 없는 것만 추가해요.
  - 정기 점검(`/etc/cron.d/b200`): 우리 GPU만 봐요.
  - 접속 설정 파일(`/etc/profile.d/b200*.sh`): 우리 계정이 아니면 바로 끝나요.

## 공용 계정이 root 가 되는 길을 막는 방법

### 공용 계정의 sudo·docker 그룹 확인

공용 계정에 sudo 나 docker 그룹이 있으면 팀원 누구든 root 가 될 수 있어요. 그러면 아래 잠금이 모두 의미가 없어져요.
지금은 둘 다 없어요. 다만 서버 관리 팀이 나중에 넣을 수도 있어서, `admin_setup.sh` 를 실행할 때마다 **확인만** 하고 있으면 `[주의]` 로 알려 줘요(바꾸지는 않아요).

### `/app` 잠금

root 로 도는 스크립트(설치, 관리자 설정, 정기 점검)는 **공용 계정이 쓸 수 있는 곳에 파일을 만들거나 권한을 바꾸지 않아요.**
`chown`·`chmod` 와 파일 쓰기는 링크를 따라가요. 공용 계정이 `/app/shared` 나 기록 파일 자리에 `/etc` 로 가는 링크를 미리 심어 두면, root 가 시스템 파일의 주인이나 내용을 바꾸게 돼요. 이 저장소에서 실제로 재현했어요.

| 곳 | 주인 | 누가 써요 |
|---|---|---|
| `/app`, `/app/shared`, `/app/inbox`, `/app/state` | root | root |
| `/app/state/reports`, `gpu_log`, `notice` | root | 정기 점검(root) |
| `/app/workspace`, `/app/state/history`, `images`, `notice_seen` | 공용 계정 | 팀원, docker 도우미 |

`admin_setup.sh` 는 실행할 때마다 이 주인을 다시 맞추고, 위 폴더 중 링크가 있으면 멈춰요. 공용 계정 홈에 쓸 일(링크, `.docker/config.json`)은 공용 계정 권한으로 해요.

### `/app/inbox` 잠금

관리자는 `/app/inbox` 의 스크립트를 root 로 실행해요. 이 폴더를 공용 계정이 고칠 수 있으면, 누구든 스크립트에 한 줄을 넣어 root 로 실행시킬 수 있어요. 그래서 설치 파일은 **root 계정의 FileZilla로** 올려요.

### 누구나 정할 수 있는 값

정기 점검(root)은 도커 이름표, 프로세스 환경의 이름, NAS의 점검 파일처럼 **누구나 정할 수 있는 값**을 읽어요. 이런 값은 이름·숫자 모양이 맞을 때만 쓰고, 계산식이나 파일 경로에 그대로 넣지 않아요.
예를 들어 이름표에 줄바꿈과 계산식을 넣으면 root 가 그 안의 명령을 실행하는 구멍이 있었고, 재현한 뒤 막았어요.

## HIWARE 기록

HIWARE는 접속 기록과 세션 녹화를 HIWARE 관리 화면에 남겨요. 보통 보안 담당이 관리하고, 서버 관리자가 직접 보지는 못해요. 그래서 평소에는 쓰지 않아요.
심각한 일이 생겼을 때만 보안 담당에게 시간과 계정(`shareduser`)을 알려 주고 확인을 요청하세요.

서버 안에서는 이름별 명령 기록(`/app/state/history/<이름>.bash_history`)이 남지만, 공용 계정이 고칠 수 있는 파일이라 참고용이에요.
