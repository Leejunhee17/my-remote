# B200 서버를 Ubuntu로 다시 설치할 때

B200 서버를 RHEL 9에서 Ubuntu로 바꾸기로 했어요. 이 문서는 서버 관리 팀에 요청할 내용과, 다시 설치한 뒤 반입을 처음부터 하는 순서예요.
Ubuntu 버전은 아직 정해지지 않았지만, 반입 묶음은 **Ubuntu 22.04 이상**이면 어느 버전에서나 그대로 써요.

## 서버 관리 팀에 요청할 것

| 항목 | 요청 내용 | 이유 |
|---|---|---|
| Ubuntu 버전 | 22.04 LTS 또는 24.04 LTS. 고를 수 있다면 24.04 | 묶음은 glibc 2.35(22.04) 이상에 맞춰 만들어요. 더 새 버전은 NVIDIA 드라이버와 CUDA 13 지원 목록에 있는지 먼저 확인해 달라고 하세요 |
| NVIDIA 드라이버 | 580 이상, open 커널 모듈(예: `nvidia-driver-580-open`) | 공용 휠의 torch가 CUDA 13.0용이에요. B200은 open 커널 모듈만 지원해요 |
| Fabric Manager | 드라이버와 같은 버전의 `nvidia-fabricmanager` 와 `nvlsm` 설치, 서비스 켜기 | HGX B200 보드는 이게 없으면 CUDA가 GPU를 쓰지 못해요(오류 802) |
| Persistence mode | `nvidia-persistenced` 켜기 | GPU를 처음 쓸 때 몇 초씩 기다리지 않아요 |
| `/app` | 2 TB SSD를 `/app` 에 연결하고, 공용 계정에 쓰기 권한 주기. **가능하면 `/app` 은 포맷하지 않기** | `/app` 이 남으면 데이터셋과 모델을 다시 올리지 않아도 돼요 |
| 계정 | 팀원이 같이 쓰는 계정 하나, 이전과 같은 이름 | 공용 폴더 경로가 홈 경로를 따라가요 |
| 시스템 라이브러리 | `libgl1 libegl1 libgomp1` | open3d가 이 라이브러리를 써요. 나머지 패키지는 없어도 돼요 |

관리자 권한이 필요한 것은 위 목록뿐이에요. 기초 프로그램과 공용 휠은 지금처럼 관리자 권한 없이 설치해요.

## 포맷하기 전에

- `/app` 을 포맷하는지 서버 관리 팀에 확인하세요.
- `/app` 도 포맷한다면 팀원들이 `~/workspace` 의 실험 결과를 NAS에 옮겨 두게 하세요.
- 접근 PC의 `D:\b200\datasets`, `D:\b200\models` 폴더는 지우지 마세요. `/app` 이 지워지면 이 폴더를 그대로 다시 올리면 돼요.
  데이터셋은 OS와 상관없어서 다시 받을 필요가 없어요. 모델은 `models_download.ps1` 을 다시 실행하면 목록에서 빠진 예전 모델을 지우고 새 목록의 모델만 받아요.

## 다시 설치한 뒤 순서

### 0. 서버 점검

`server\check_server.sh` 하나만 B200 서버의 `/app/inbox` 에 올려 실행하세요. 관리자 권한이 없어도 되고, 서버에 아무것도 바꾸지 않아요.
`/app/inbox` 가 없으면 올리기 전에 `mkdir -p /app/inbox` 로 만드세요.

```bash
# [B200 서버] 터미널
bash /app/inbox/check_server.sh
```

운영체제, glibc, 드라이버, GPU 8장, NVLink Fabric, `/app` 쓰기 권한과 SSD 여부, 시스템 라이브러리를 확인해요.
`[문제]` 가 있으면 화면 끝의 "고칠 것" 목록을 서버 관리 팀에 그대로 보내세요.

### 1. 공용 휠·기초 프로그램

접근 PC에서 묶음을 새로 만드세요. glibc 기준이 2.35로 올라가고, RHEL에서는 못 쓰던 open3d가 들어가요.
RHEL 때 받아 둔 `D:\b200\pack` 폴더는 지우지 않아도 돼요. 스크립트가 버전이 같은 파일은 다시 쓰고, 새 목록에 없는 예전 파일은 지운 뒤 필요한 것만 새로 받아요. 묶음 파일(`b200-pack.tar`)도 매번 새로 만들어요.

```powershell
# [접근 PC] PowerShell
cd D:\b200
git pull
powershell -ExecutionPolicy Bypass -File .\pc\pack_build.ps1
```

`pack\b200-pack.tar` 를 `/app/inbox` 에 올리고 **root 로** 설치하세요. root 로 깔아야 2단계에서 공용 폴더를 잠근 뒤에도 그대로 써요.

```bash
# [B200 서버] root
cd /app/inbox && tar xf b200-pack.tar && bash pack_install.sh /app/shared
```

`/app/shared` 가 포맷 전 그대로 남아 있다면, 기초 프로그램을 한 번 새로 까는 것을 권해요.

```bash
# [B200 서버] root
cd /app/inbox && B200_REBUILD_TOOLS=1 bash pack_install.sh /app/shared
```

### 2. 관리자 기본 설정

1단계 묶음에 같이 들어 있는 `admin_setup.sh` 를 root 로 실행하세요. 공용 계정에서 관리자 권한을 빼고, 공용 폴더를 잠그고, 접속할 때 이름을 묻게 해요. 자세한 내용은 `docs/6_서버_관리.md` 에 있어요.

```bash
# [B200 서버] root
cd /app/inbox && bash admin_setup.sh
```

끝나면 `/app/shared/team.txt` 에 팀원 `이름 그룹` 을 적고 한 번 더 실행하세요(작업 폴더가 생겨요).

### 3. 도커

```powershell
# [접근 PC] PowerShell
powershell -ExecutionPolicy Bypass -File .\pc\docker_pack.ps1
```

`pack_docker\b200-docker.tar` 를 `/app/inbox` 에 올리고 root 로 설치하세요.

```bash
# [B200 서버] root
cd /app/inbox && tar xf b200-docker.tar && bash docker_install.sh
```

### 4·5. 데이터셋과 모델

- `/app` 이 남아 있으면 할 일이 없어요. 0단계 점검 화면에 "예전 데이터셋이 남아 있다" 가 나와요.
- `/app` 이 지워졌으면 README의 4·5단계를 그대로 하세요. 접근 PC에서 다시 받지 않고, 있는 `datasets`, `models` 폴더를 올린 뒤 설치 스크립트만 root 로 실행하면 돼요.

## 달라지는 것

| | RHEL 9 | Ubuntu |
|---|---|---|
| 터미널 모양 | `[아이디@서버이름 ~]$` | `아이디@서버이름:~$` |
| 묶음 glibc 기준 | 2.34 | 2.35 |
| open3d | 못 씀 | 씀(`libgl1` 필요) |
| 공용 폴더 경로, 명령, 팀원 사용법 | | 바뀌지 않아요 |
