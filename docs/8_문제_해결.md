# 문제 해결

반입·설치 스크립트가 멈추거나 `[문제]` 를 보여 줄 때, 화면에 나온 메시지로 해결 방법을 찾는 문서예요.
팀원이 컨테이너를 쓰다가 막혔다면 `team/사용_안내.md` 의 "자주 묻는 질문" 을 보세요.

## 먼저 할 일

1. 화면의 `멈춤` 상자나 `[문제]` 줄에 적힌 **할 일** 을 하세요.
2. 같은 명령을 다시 실행하세요. 모든 스크립트는 다시 실행해도 돼요. 끝난 것은 건너뛰고, 받다 만 것은 이어서 받아요.
3. 그래도 안 되면 아래 표에서 메시지를 찾으세요.

## 접근 PC에서 나는 문제

| 메시지 | 할 일 |
|---|---|
| `스크립트를 실행할 수 없습니다` | `-ExecutionPolicy Bypass` 가 빠졌어요. `docs/1_처음_설치.md` 의 명령을 그대로 복사해 실행하세요 |
| `파일을 찾을 수 없습니다` (`.\pack_build.ps1` 등) | 스크립트가 `pc\` 폴더로 옮겨졌어요. `.\pc\pack_build.ps1` 처럼 실행하세요 |
| `uv가 없어요`, `micromamba가 없어요` | 설치한 뒤 PowerShell 창을 새로 여세요. 그래도 안 되면 `uv.exe`, `micromamba.exe` 를 `D:\b200` 에 넣으세요. micromamba 위치는 PowerShell에서 `$env:MAMBA_EXE` 로 확인할 수 있어요 |
| `인터넷: … 접속 안 됨` | 회사망 문제(인증서 폐기 확인, 윈도우 프록시)는 스크립트가 스스로 우회해요. 그래도 안 되면 사내 IT에 프록시 주소를 물어 `.env` 에 `HTTPS_PROXY=http://프록시주소:포트` 를 적으세요 |
| `.env … 번째 줄을 읽지 못했어요` | `.env` 의 그 줄이 `이름=값` 모양이 아니에요. 설명을 적을 때는 줄 맨 앞에 `#` 을 붙이고, 값에 공백 뒤 `#` 이 들어가면 `"따옴표"` 로 감싸세요 |
| `모르는 작업이에요` | `.env` 의 `B200_RUN` 이나 `-Run` 뒤에는 `pack`, `docker`, `datasets`, `models` 만 쓸 수 있어요 |
| `micromamba가 conda-forge 목록을 받지 못했어요` | 화면의 `[문제]` 아래 줄과 경고를 담당자에게 보내 주세요 |
| `WildScenes2d 폴더를 찾지 못했어요`, `접속 정보가 만료됐거나 막혔어요` | WildScenes 접속 정보는 약 48시간만 유효해요. 포털에서 새로 받아 같은 명령을 다시 실행하세요 |
| `Google Drive 접속 안 됨` | 지금 접근 PC에서는 막혀 있어요. RELLIS-3D, TAS500, GO만 건너뛰고 나머지는 받아요 |
| WildScenes에서 `CSIRO S3 저장소에 접속되지 않아요`, `curl 오류 56` | 포털(data.csiro.au)은 열려도 실제 파일 서버 `s3.data.csiro.au` 가 회사 프록시·방화벽에 막힌 경우예요. 화면에 `CONNECT tunnel failed, response 403` 이 있으면 프록시가 거절한 거예요. 사내 IT에 `s3.data.csiro.au` (포트 443) 허용을 요청하세요. 브라우저에서는 `https://s3.data.csiro.au/` 가 401·AccessDenied라도 뜬다면, 스크립트가 브라우저와 같은 프록시와 윈도우 로그인 인증을 자동으로 찾아 써요. 그래도 AWS CLI 단계에서 막히면 `docs/6_데이터셋.md` 의 "WildScenes 링크 목록으로 받기" 로 받으세요 |
| Google Drive에서 `403` | `.\pc\datasets_download.ps1 -DriveCheck` 로 이유를 보세요. 이유별 할 일은 `docs/6_데이터셋.md` 의 "Google Drive 데이터셋 받기" 에 있어요 |

## GPU 서버에서 나는 문제

| 메시지 | 할 일 |
|---|---|
| `올리는 중에 파일이 깨졌어요`, `올리는 중에 깨졌거나 빠진 파일이 있어요` | 화면에 나온 파일만 접근 PC에서 `/app/upload` 에 다시 올리고, `/app/inbox` 의 같은 자리에 복사하세요. 1·3단계라면 묶음 파일(`.tar`)을 다시 올려 복사한 뒤 다시 푸세요 |
| `남은 공간이 … GB예요` | 다 푼 `.tar` 파일과 `/app/upload` 의 원본을 지우세요. 홈(10 GB)에 설치하려 했다면 `bash pack_install.sh /app/shared` 처럼 `/app` 경로를 붙이세요 |
| `GPU 서버의 glibc(…)가 묶음 기준(…)보다 낮아서 안 맞아요` | Ubuntu 22.04보다 오래된 OS예요. 화면에 나온 `-Glibc` 값을 붙여 접근 PC에서 1단계를 다시 실행하고, 새 묶음 파일을 올리세요 |
| `b200 doctor` 에서 `GPU 계산 이상` 이나 오류가 나와요 | `bash /app/inbox/check_server.sh` 로 드라이버와 NVLink 상태를 보고, `[문제]` 목록을 서버 관리 팀에 보내세요. 오류에 `802` 가 있으면 Fabric Manager 문제예요(HGX 보드일 때만. 지금 H200 NVL 은 해당 없어요) |
| `기초 프로그램에 없는 명령: …` | `lists/tools.txt` 의 패키지 이름이 실제 명령과 다른 경우예요. 패키지 이름이 맞는지 conda-forge 에서 확인하세요 |
| 서버의 `sha256sum` 지문이 접근 PC 화면의 지문과 달라요 | 올리는 중에 깨졌거나 누군가 바꾼 거예요. **실행하지 마세요.** `/app/upload` 와 `/app/inbox` 의 그 파일을 지우고 다시 올려 새로 복사하세요 |
| `올린 폴더에 링크가 있어서 복사본을 지웠어요`, `안에 링크가 있어요(올린 폴더에 누가 넣었을 수 있어요)` | 올린 데이터셋·모델 폴더에 링크가 섞여 있어요. `/app/upload` 의 폴더를 지우고 접근 PC 폴더를 다시 올린 뒤 `/app/shared/bin/b200 fetch <이름>` 을 다시 실행하세요 |
| `체크섬 목록에 없는 파일 …개는 옮기지 않아요` | 접근 PC에서 받지 않은 파일이 올린 모델 폴더에 들어 있어요. 일부러 넣은 게 아니면 누가 넣었는지 확인하세요. 필요한 파일이면 접근 PC의 목록(`lists/models.txt`)으로 받아 다시 올리세요 |
| `/app이 아직 잠기지 않았어요`, `/app이 잠기지 않았거나 /app/docker가 링크예요` | 관리자 기본 설정을 먼저 하세요: `cd /app/inbox && bash admin_setup.sh`. 그다음 같은 명령을 다시 실행하세요 |
| `root로 설치할 때는 설치할 곳을 붙여 실행하세요` | `bash pack_install.sh /app/shared` 처럼 경로를 붙이세요 |
| `/app 을 다른 계정도 써요`, `/app 잠금 보류` | 서버 2처럼 다른 팀이 `/app` 에 폴더를 둔 경우예요. 서버 관리 팀, 다른 팀과 협의한 뒤 PuTTY 화면에서 `admin_setup.sh` 를 직접 실행해 `y` 로 진행하세요 |
| `쓸 수 없는 이름이라 건너뛰어요`, `gpu_alloc.txt에 없는 그룹이에요` | `/app/shared/team.txt` 의 이름에서 `-`, `/` 를 빼고, 그룹은 `gpu_alloc.txt` 의 그룹 이름과 글자까지 같게 고친 뒤 `admin_setup.sh` 를 다시 실행하세요 |
| `root로 실행하면 다른 계정이 쓰는 폴더는 측정하지 않아요` | `check_network.sh disk` 를 root 로 공용 계정 폴더에 대해 실행한 경우예요. 같은 디스크의 root 폴더에서 측정하세요: `bash check_network.sh disk /app/inbox` |
| `라벨을 못 찾음` | 화면의 "지금 구조" 를 보고 `docs/6_데이터셋.md` 의 "학습 코드가 읽는 라벨 위치" 대로 폴더를 옮기세요 |

## 그래도 안 되면

아래 기록 파일을 담당자에게 보내 주세요.

| 어디서 | 기록 파일 |
|---|---|
| 접근 PC | `D:\b200\pack\build.log`, `D:\b200\pack_docker\build.log`, `D:\b200\datasets\download.log`, `D:\b200\models\download.log` |
| GPU 서버 | `/app/shared/logs/` 에서 가장 최근 파일. 도커 설치는 `/var/log/b200/`, 점검 보고서는 `/app/inbox/reports/`, 주간 보고서는 `/app/state/reports/` |

## 예전 서버(RHEL)에서 `~/shared` 를 큰 디스크로 옮겨야 할 때

Ubuntu로 다시 설치하기 **전**, 홈(10 GB)에 설치한 `~/shared` 를 `/app` 으로 옮길 때만 써요. 스크립트가 복사한 뒤 파일 수와 크기를 비교하고 홈에 같은 이름의 링크를 남겨서 경로와 설치된 환경을 그대로 쓸 수 있어요.
Ubuntu에서는 처음부터 `/app/shared` 에 설치하고 `admin_setup.sh` 가 `/app` 을 잠그니까 이 스크립트는 쓰지 않아요.

```bash
# [예전 GPU 서버] 공용 계정 터미널. 예전 서버에서는 묶음을 ~/inbox 에 풀었어요
bash ~/inbox/move_shared.sh /app
```

Ubuntu로 바꾼 뒤에는 `admin_setup.sh` 가 이렇게 옮긴 `/app/shared` 에서 데이터셋·모델과 명단·설정 파일만 남기고, 기초 프로그램 같은 실행 파일은 `/app/.shared_old_<날짜>` 로 치워요(공용 계정이 만든 프로그램을 root 가 실행하지 않게). 기초 프로그램은 `pack_install.sh` 로 다시 설치해요.
