# 문제 해결

반입·설치 스크립트가 멈추거나 `[문제]` 를 보여 줄 때, 화면의 메시지로 찾아 해결하는 문서예요.
팀원이 컨테이너를 쓰다 막힌 경우는 `team/사용_안내.md` 의 "자주 묻는 질문" 을 보세요.

## 먼저 할 일

1. 화면의 `멈춤` 상자나 `[문제]` 줄에 적힌 **할 일** 을 하세요.
2. 같은 명령을 다시 실행하세요. 모든 스크립트는 다시 실행해도 돼요. 끝난 것은 건너뛰고, 받다 만 것은 이어서 받아요.
3. 그래도 안 되면 아래 표에서 메시지를 찾으세요.

## 접근 PC에서 나는 문제

| 메시지 | 할 일 |
|---|---|
| `스크립트를 실행할 수 없습니다` | `-ExecutionPolicy Bypass` 가 빠졌어요. `docs/1_처음_설치.md` 의 명령을 그대로 복사해 실행하세요 |
| `파일을 찾을 수 없습니다` (`.\pack_build.ps1` 등) | 스크립트가 `pc\` 폴더로 옮겨졌어요. `.\pc\pack_build.ps1` 처럼 실행하세요 |
| `uv 가 없다`, `micromamba 가 없다` | 설치한 뒤 PowerShell 창을 새로 여세요. 그래도 안 되면 `uv.exe`, `micromamba.exe` 를 `D:\b200` 에 넣으세요. micromamba 위치는 PowerShell에서 `$env:MAMBA_EXE` 로 확인할 수 있어요 |
| `인터넷: … 에 접속 안 됨` | 스크립트가 회사망 문제(인증서 폐기 확인, 윈도우 프록시)는 스스로 우회해요. 그래도 안 되면 사내 IT에 프록시 주소를 물어 실행 전에 `$env:HTTPS_PROXY = "http://프록시주소:포트"` 를 입력하세요 |
| `micromamba 가 conda-forge 목록을 받지 못했다` | 화면의 `[문제]` 아래 줄과 경고를 담당자에게 보내 주세요 |
| `WildScenes2d 폴더를 찾지 못했다`, `접속 정보가 만료됐거나 막혔다` | WildScenes 접속 정보는 약 48시간만 유효해요. 포털에서 새로 받아 같은 명령을 다시 실행하세요 |
| `Google Drive 접속 안 됨` | 지금 접근 PC에서는 막혀 있어요. RELLIS-3D, TAS500, GO만 건너뛰고 나머지는 받아요 |
| WildScenes에서 `CSIRO S3 저장소에 접속 안 된다`, `curl 오류 56` | 포털(data.csiro.au)은 열려도 실제 파일 서버 `s3.data.csiro.au` 가 회사 프록시·방화벽에 막힌 경우예요. 화면에 `CONNECT tunnel failed, response 403` 이 있으면 프록시가 거절한 거예요. 사내 IT에 `s3.data.csiro.au` (포트 443) 허용을 요청하세요. 브라우저에서는 `https://s3.data.csiro.au/` 가 401·AccessDenied라도 뜬다면, 스크립트가 브라우저와 같은 프록시와 윈도우 로그인 인증을 자동으로 찾아 써요. 그래도 AWS CLI 단계에서 막히면 `docs/6_데이터셋.md` 의 "WildScenes 링크 목록으로 받기" 로 받으세요 |
| Google Drive에서 `403` | `.\pc\datasets_download.ps1 -DriveCheck` 로 이유를 보세요. 이유별 할 일은 `docs/6_데이터셋.md` 의 "Google Drive 데이터셋 받기" 에 있어요 |

## B200 서버에서 나는 문제

| 메시지 | 할 일 |
|---|---|
| `올리는 중에 파일이 깨졌다` | 화면에 나온 파일만 접근 PC에서 다시 올리세요. 1단계라면 묶음 파일을 다시 올리세요 |
| `남은 공간이 … GB 다` | 다 푼 `b200-pack.tar` 를 지우세요. 홈(10 GB)에 설치하려 했다면 `bash pack_install.sh /app/shared` 처럼 `/app` 경로를 붙이세요 |
| `glibc 가 … 안 맞는다` | Ubuntu 22.04보다 오래된 OS예요. 화면에 나온 `-Glibc` 값을 붙여 접근 PC에서 1단계를 다시 실행하고, 새 묶음 파일을 올리세요 |
| `torch … 가 GPU를 못 본다` | `bash /app/inbox/check_server.sh` 로 드라이버와 NVLink Fabric 상태를 보고, `[문제]` 목록을 서버 관리 팀에 보내세요. 오류에 `802` 가 있으면 Fabric Manager 문제예요 |
| `open3d import 실패` | 서버에 `libgl1` 이 없어요. 서버 관리 팀에 `libgl1 libegl1 libgomp1` 설치를 요청하세요. 다른 패키지는 그대로 써요 |
| `기초 프로그램에 없는 명령: …` | `lists/tools.txt` 의 패키지 이름이 실제 명령과 다른 경우예요. 해당 명령을 담당자에게 알려 주세요 |
| `/app 이 아직 잠기지 않았다`, `/app 이 잠기지 않았거나 /app/docker 가 링크다` | 관리자 기본 설정을 먼저 하세요: `cd /app/inbox && bash admin_setup.sh`. 그다음 같은 명령을 다시 실행하세요 |
| `root 로 설치할 때는 경로를 준다` | `bash pack_install.sh /app/shared` 처럼 경로를 붙이세요 |
| `/app 을 다른 계정도 쓴다`, `/app 잠금 보류` | 서버 2처럼 다른 팀이 `/app` 에 폴더를 둔 경우예요. 서버 관리 팀·다른 팀과 정한 뒤 터미널에서 `admin_setup.sh` 를 직접 실행해 `y` 로 진행하세요 |
| `라벨을 못 찾음` | 화면의 "지금 구조" 를 보고 `docs/6_데이터셋.md` 의 "학습 코드가 읽는 라벨 위치" 대로 폴더를 옮기세요 |

## 그래도 안 되면

아래 기록 파일을 담당자에게 보내 주세요.

| 어디서 | 기록 파일 |
|---|---|
| 접근 PC | `D:\b200\pack\build.log`, `D:\b200\datasets\download.log`, `D:\b200\models\download.log` |
| B200 서버 | `/app/shared/logs/` 에서 가장 최근 파일. 도커 설치는 `/var/log/b200/` |

## 예전 서버(RHEL)에서 `~/shared` 를 큰 디스크로 옮겨야 할 때

Ubuntu로 다시 설치하기 **전**, 홈(10 GB)에 설치한 `~/shared` 를 `/app` 으로 옮길 때만 써요. 복사한 뒤 파일 수와 크기를 비교하고, 홈에는 같은 이름의 링크를 남겨서 경로와 설치된 환경을 그대로 쓸 수 있어요.
Ubuntu에서는 처음부터 `/app/shared` 에 설치하고 `admin_setup.sh` 가 `/app` 을 잠그므로 쓰지 않아요.

```bash
# [예전 B200 서버] 터미널
bash /app/inbox/move_shared.sh /app
```
